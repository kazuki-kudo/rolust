**設計判断**:

- アカウント ID ごとに 1 行へ束ねる。登録操作の単位が「1 アカウント ID ＋ 複数ユーザ名」（C-5）であるため、表示もその単位に合わせると登録操作との対応が取れる。ユーザ 1 件 1 行にすると、同じアカウント ID が縦に繰り返され混在の構造が読めない。 [FR: C-5][derived]
- ARN は一覧に出さない。`arn:aws:iam::<accountId>:user/<userName>` はアカウント ID とユーザ名から機械的に導出でき（FR-1.2）、両方が表示済みであるため冗長。ARN が必要な場面（管理外プリンシパルとの突き合わせ）は FR-7.4 で扱う。 [FR-1.2][derived]
- **「ユーザを登録」のアカウント ID 初期値**（Issue #60 により 2026-09-28 追記）: モーダルを開いたとき、AWS アカウント ID 欄に最後に登録された（`createdAt` が最大の）IamUser のアカウント ID を初期値として入れる。IamUser が 0 件のときは空のままにする。初期値は通常の入力欄なので自由に上書きでき、検証（12 桁の数字）は変えない。 [FR-1.4][derived]
- **「ユーザを登録」の CSV 入力**（Issue #98 により 2026-10-04 追記）: モーダルの上部に「登録の方法」の切り替え（「1 件ずつ」「CSV」。Cloudscape `SegmentedControl`）を置く。AWS アカウント ID の欄は両方で共通で、モードを切り替えても入力は残る。CSV では、ユーザ名のテキストエリアの代わりに CSV のテキストエリアを出し、その上に形式の説明（1 行目のヘッダは入力済み、「ユーザ名」列が必須、ほかの列名は属性列の名前、区切りはカンマ、1 回 500 行まで、登録済みのユーザは変更しない、1 行でも不正なら何も登録しない）と、データ行の例を 1 行出す。（Issue #207 により 2026-11-01 訂正。訂正前は「1 行目はヘッダ」と、属性列名から組み立てたヘッダと 1 行の例を説明に出した）**ヘッダ行の初期入力**（Issue #207 により 2026-11-01 追記）: モーダルを開いたとき、CSV の入力欄の 1 行目に「ユーザ名」と属性列名を順に並べたヘッダ行を入れる（利用者は 2 行目以降にデータを足す）。属性列が 0 件のプールは「ユーザ名」だけ。名前にカンマ・二重引用符・改行があるときは CSV の規則（RFC 4180）で引用符で囲み、そのまま登録できる。入力を直した後にモードを切り替えて戻っても上書きしない（空にした場合も空のまま）。閉じるとモーダルの入力は破棄するので、開き直すとヘッダに戻る。ヘッダに触れていなければ、閉じるときの破棄確認は出さない（GI-4）。ヘッダだけのまま登録すると「登録するユーザの行がありません」のエラーで、送らない。検証は blur 時と送信時に表示し、エラーは「n 行目: …」の一覧で出す（50 件まで。超える分は「ほか n 件のエラーがあります」）。成功の通知は「IAM ユーザを n 件登録しました」に、登録済みで変更しなかった人数があれば「（登録済みのため変更なし m 件）」を添える。書き込みの途中で失敗したときは、同じ CSV をそのまま再送できる旨を添える。 [FR-1.10]

「記録を IAM に合わせる」は、押すと、**同じ詳細モーダルが確認の状態（同じモーダル内）に切り替わる**（API は呼ばない。2 枚目のモーダルは出さない。GI-10）。本文の先頭に警告の枠（見出し「<ロール名>: 記録を IAM に合わせる」）を差し込み、乖離の一覧と 2 つの操作は本文に残す（2 つの操作は確認の間は無効）。フッタは「キャンセル」と「記録を合わせる」に替わり、「閉じる」（primary）は確認の間だけ消える。枠には、取り込む（IAM にいて記録にいない）ユーザと、外す（記録にいて IAM にいない）ユーザの ARN 全文を並べ、AWS の信頼ポリシーは書き換えないこと、そのユーザの未反映の編集（チェックの変更）は上書きされることを示す。「記録を合わせる」は primary にしない（記録を書き換える操作）。

| ReadOnlyAudit の信頼ポリシーの乖離                            |
| (!) ReadOnlyAudit: 記録を IAM に合わせる                      |
|     Rolust の記録を、IAM の信頼ポリシーの現状に合わせます。    |
|     AWS の信頼ポリシーは書き換えません。                      |
|     記録に取り込む（IAM にいる）                              |

|     記録から外す（IAM にいない）                              |

|   （足りない・余分・参考の一覧は、このまま下に残る）          |

**設計判断**:

- **列ヘッダは 3 段構成**（ロール名 / アカウント ID / 選択チェックボックスまたは状態チップ）。ロール名だけでは同名ロールが別アカウントに存在する場合に区別できない。 [FR-2.2][derived]（Issue #150 により 2026-10-08 追記。1 段目の名前は表示名（無ければ正式名）。詳細は次の項目）
- **説明はロール名のツールチップで示す**（Issue #21 により 2026-09-27 追記）。段数は増やさず、説明のあるロールはロール名にネイティブ tooltip（`title`）を添える。列ヘッダは幅が狭く、常時表示する補助行にすると列が広がりすぎるため（NFR-1）。 [FR-2.3][derived]（Issue #150 により 2026-10-08 追記。列ヘッダの名前は表示名（無ければ正式名）。ホバーは表示名がある列で正式名を 1 行目、説明を 2 行目）
- **変更のあった列は自動でプリセレクト**。管理者がチェックを増減した直後に「申請を作成」を押すのが最短の動線であり、変更した列を毎回手で選び直させるのは冗長。選択解除は可能なので、取捨選択の自由は失われない。 [Q4][derived]
- **除外は列ヘッダの状態チップと警告帯の 2 箇所で伝える**。チップは「その列が今どうなっているか」を局所的に、警告帯は「何件除外されたか・なぜか・どうすれば解けるか」を大域的に伝える。片方だけでは、横スクロールで列が視界外に出たとき（チップのみ）または列との対応が取れないとき（帯のみ）に伝達が切れる。 [Q4][FR-4.6][derived]
- **変更は色だけで表さない**。追加は `+`、削除は `−` の記号を併記する。色覚特性に依存しない伝達のため。 [Q2][ux]
- **行ヘッダ・列ヘッダをスクロール固定**。マトリクスは縦横とも伸びるため、どちらかが視界外に出ると交点セルの意味が失われる。 [Q3][ux]（Issue #91 により 2026-10-04 訂正: 縦の固定は、外側の div が縦に上限を持たず `sticky` の基準がページ全体になっていたため効いていなかった。スクロール領域に高さの上限を付け、縦横ともマトリクスの内側でスクロールさせて直した。）
- **チェック操作は即座に Assignment として保存する**。保存ボタンは置かない。FR-3.2 が「チェック増減を Assignment として保存し、その時点では AWS へ一切書き込まない」と定めており、保存ボタンを置くと「保存＝反映」と誤解される危険がある。保存状態はツールバーに `保存済み` の微細なテキストで示す。 [FR-3.2][ux][derived]
- **プール選択欄**（Issue #17 により 2026-09-25 追記。Issue #108 により 2026-10-05 に廃止）: UserPool が固定の 1 つなので、ヘッダの選択欄は無い。 [FR-1.6]
- **ツールバーの「ロールの紐づけ」**（廃止。Issue #135 により 2026-10-07）: ツールバーには「変更を取り消す」と「申請を作成」だけが残る。ロールの登録は画面 2 で行う。旧仕様は Issue #46・#79・#80 の spec にある。 [FR-2.1]
- **「変更を取り消す」を置き、「選択をリセット」は置かない**（Issue #88 により 2026-10-03）: 「選択をリセット」は列ヘッダのチェック（申請に含めるロールの選択）を戻すだけで、交点セルは戻らない。交点にチェックを入れた列は自動で選択され（DF-4）、リセット後も「変更のある全列を選択」なので、押しても見た目が変わらず、名前から「交点が戻る」と誤解された。利用者が要るのは交点の未反映の変更の取り消しなので、ツールバーに 1 つだけ置き、表示中のプールの全列を対象にする（列ごとには置かない。列ヘッダは 3 段で幅が狭いため）。未反映の申請がある列は対象外にし、確認で対象外の数を示す。確認を挟み（GI-4）、AWS へは書かない（FR-3.2）。一括の API を 1 本にしたのは、セル単位の即時保存（MQ-4）が避けたのは「まとめて保存すると巻き戻し対象が曖昧になる」ことであり、「`reflected` にそろえる」は対象が一意に決まるため。取り消しは冪等で、途中で失敗してもやり直せる。 [FR-3.2][FR-4.5][derived]
- **ソート・フィルタは列ヘッダの「▾」メニューに置く**（Issue #91 により 2026-10-04）: 各ロール列の見出しの「▾」から、その列の値でユーザ行を絞り・並べる（Excel のオートフィルタと同じ位置と向き）。ツールバーに選択欄を並べる案は、列ごとに条件を重ねられず、対象の列と操作が離れるので採らない。ソートは「チェックありを上に」「チェックなしを上に」「解除」（1 列だけ）、フィルタは「すべて」「チェックあり」「チェックなし」「未反映の変更あり」（列をまたいで AND）。絞り込み中は、マトリクスの上に件数の行「表示 n / 全 m 行」と「すべて解除」を出し、条件のある列ヘッダに語のバッジ（「↑ チェックあり」「絞り込み: …」）を出す（色だけに頼らない）。表示する行と順序は条件を変えたときに確定し、セルのチェックでは動かさない（絞り込み中にチェックを外して行が消えると、フォーカスを失うため）。列ヘッダの「変更 n」と「申請に含める」は絞り込みに関係なく全行で数える（申請は列単位で、行では絞らないため）。条件は保存せず、マトリクスの読み直しとプールの切り替えでリセットされる（列の非表示と畳みは別で、保存する。FR-3.6。Issue #140 により 2026-10-07 追記）。AWS へは書かない（FR-3.2）。キーボードでは、ヘッダのセルで Enter を押すとメニューが開く（`interaction-spec.md`）。 [FR-3.3][derived]
- **ユーザのテキスト絞り込み**（Issue #106 により 2026-10-04 追記）: 件数の行の上に、検索欄「ユーザ名・アカウント ID・属性で絞り込み」（Issue #107 により 2026-10-04 訂正。訂正前は「ユーザ名・アカウント ID で絞り込み」）を 1 つ置く。入力した語を、ユーザ名・アカウント ID・畳んでいない属性の値に対して部分一致（大文字小文字を無視、前後の空白は無視、入力全体を 1 語）で照合し、列のフィルタと AND で効かせる。ソートは残った行の並びに効く。行見出し（角のセル）のメニューには入れない（テキスト入力はメニューに向かず、角のセルはマトリクスの Tab 停止点 1 つの約束に絡むため）。絞り込み中の件数の行「表示 n / 全 m 行」と「すべて解除」、0 件の本体は列の条件と共用する。「すべて解除」は入力も空にする。列ヘッダの「変更 n」と「申請に含める」は全行で数える。属性による絞り込みは、マトリクスに属性を出す Issue #107 の後（Issue #107 により 2026-10-04: 回収した。次の「属性列」）。 [FR-3.3][derived]

- **ロール列を隠す**（Issue #140 により 2026-10-07 追記）: 各ロール列の「▾」メニューに「この列を隠す」を置く。選択中のロール（「申請に含める」を入れた列）は隠せず、項目を無効にして「申請に含めている列は隠せません」と理由を出す（申請の対象は明示した選択だけなので、選択中の列は常に見えている）。隠すと列は消え、フォーカスは右隣（右端なら左隣）の列のヘッダの操作へ移る。件数の行に「非表示 n 列」（変更のある列があれば「（変更あり m 列）」）のボタンを出し、押すと一覧が開く。一覧は、ロール名（変更あり・条件あり〈フィルタ・ソート〉の添え書き）ごとに「表示する」と、末尾に「すべて表示」を持つ。隠した列の変更は申請に入らず（選択していないため）、読み込み直しでも自動選択されない。隠した列のフィルタ・ソートは有効のまま残る。すべての列を隠したときは、ヘッダと件数の行を残し、本体に「すべての列を隠しています」と「すべて表示」を出す。隠したロールと畳んだ属性列は、管理者ごとにブラウザへ保存する。AWS へは書かない（FR-3.2）。 [FR-3.6]

## Screen Flow

`requirements.md` の `### 画面遷移` を継承し、各遷移にトリガーと戻り経路を補う。 [FR-7.3][FR-7.4][FR-7.5]

```
   [FR-7.1 IAMユーザ管理]        [FR-7.2 IAMロール管理]
              |                              |
              |  登録したプール/ロールを使う   |
              +--------------+---------------+
                             v
                  [FR-7.3 IAMロール割り当て]
                             |
                             |  「申請を作成」（列ヘッダで複数ロール選択）
                             v
                  [FR-7.4 差分確認・反映] <-------------+

                             |  反映（結果が履歴に残る）   | 下書き再開 /
                             v                          | 失敗の再反映
                  [FR-7.5 申請履歴] ---------------------+
                             |
                             |  破棄（確認モーダル）
                             v
                  [FR-7.5 申請履歴]（状態「破棄」で残る）
```

**遷移の実装**: DF-5 により SPA であるため、すべてクライアント側ルーティング。FR-7.4 は ChangeRequest 群を指す URL（例 `/requests?ids=...`）を持ち、ブラウザの戻る操作と再読み込みで同じ画面に復帰できる。FR-4.7 が「セッションをまたいで下書きを再開できる」ことを要求しているため、FR-7.4 は URL から状態を復元できなければならない。 [FR-4.7][FR: C-2][derived]
