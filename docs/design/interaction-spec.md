**表のヘッダ行の固定**（Issue #133 により 2026-10-06 追記）: ページ全体を縦にスクロールする画面の表（画面 1 の IamUser の表、画面 2 のロール一覧、画面 5 の申請一覧）は、列ヘッダ行を固定する。絞り込み欄を持つ表では、欄と列ヘッダ行が一緒に固定される。固定の位置はトップナビの直下で、トップナビ自体も画面上端に固定する。割り当てマトリクスは、マトリクスの内側でスクロールする自前の固定（Issue #91）で、この規約の対象外。モーダル内の表（ロールの紐づけ）は固定しない。

マトリクスは Tab が全交点セル（将来は数百 × 数百）を通るため、列ヘッダおよびツールバーへの到達が遠くなる。これを解消するため次を設ける。

| 機構 | 挙動 |
|---|---|
| スキップリンク | マトリクス直前に「マトリクスを飛ばして申請操作へ」の視覚的に隠されたリンクを置く。フォーカス時に可視化し、Enter でツールバーの「申請を作成」へフォーカスを移す |
| 矢印キー移動 | マトリクス内は矢印キーでセル間を移動する（グリッドのローミング tabindex）。Tab はマトリクス全体を 1 つの停止点として扱い、抜けるときは次の要素へ飛ぶ |
| Home / End | 行頭・行末のセルへ移動 |
| Space | フォーカス中のセルのチェックを切り替える |

矢印キー移動を採ることで、Tab の停止点はマトリクス全体で 1 つになり、列数・行数が増えてもキーボード動線は伸びない。これは AN-3 の解決策であり、同時に Q2=`C` の Must（全機能キーボード操作可）を満たす。 [AN-3][Q2][ux]

### 権限（FR-6.5。Issue #141 により 2026-10-07 追記）

起動時に `GET /me` を 1 回読み、結果を全画面で共有する。

| 状態 | 表示 |
|---|---|
| 確認中 | 画面を出さず、「権限を確認中」の待機表示を出す。操作できる状態で画面を出さない |
| 失敗 | 画面を出さず、エラーパネルと再試行ボタンを出す |
| 権限なし（`none`） | 画面本体の位置に「操作できる権限がありません」の案内を出す。ナビゲーションは残す。API は参照も 403 にする |
| 参照（`view`）・作成（`edit`）・反映（`apply`） | 画面を出す。必要な権限に足りない操作は、無効にして理由を出す（GI-13） |

無効にする操作: 画面 1 の「ユーザを新規登録」「属性の項目を編集」「属性一括編集モード」と行ごとの「属性を編集」「削除」、画面 2 の「ロールを新規登録」「並び順を編集」と行ごとの説明・色の編集・削除、画面 3 のセルとロール見出しのチェックボックス・「変更を取り消す」「申請を作成」（以上 `edit`）、画面 4 の「選択した n 件を反映」（`apply`）、画面 5 の「破棄」（`edit`）。理由は、ボタンでは `disabledReason`、チェックボックスでは `title` に出す。

**管理外プリンシパルの警告** [FR-4.2][Q22]:

警告は表示のみで反映を妨げない。したがって次を守る。

- 反映ボタンを disabled にしない
- 「了解しました」のチェックボックスを要求しない（Q22 で選択肢 B・C は不採用）
- 警告の存在は色と `(!)` 記号の両方で示す（色のみに依存しない）
- 警告本文は「反映してもこれらは削除されません」と、**起きないこと**を明示する。管理者が恐れるのは意図しない削除であり、それが起きないと言い切るのが正しい伝達である [FR-5.1][derived]
- プレースホルダ（`Sid: RolustPlaceholder`）の principal は警告に出さない。Rolust 自身の Statement であり、その取り除き・挿入は PolicyDiffPanel の注記で示す（Issue #16 により 2026-09-25 追記。requirements.md FR-4.2 の注記） [FR-4.2]

## Component Specifications

`component-spec-template.md` の形式に従う。対象は **Rolust 固有の振る舞いを持つコンポーネント**であり、Cloudscape の既製部品をそのまま置くだけの箇所（`Input`、`Modal` 単体など）は含めない。

ここで仕様を書くことと、実装が自前になることは別である。`design-system-mapping.md` の `## Component Inventory` が実装区分（自前 / 既製の組み合わせ / 既製のラッパ）を定めており、本節の 5 件のうち自前実装は `AssignmentMatrix` と `SkipToActions` の 2 件、残る `ExclusionBanner` / `RequestStatusChip` / `PolicyDiffPanel` は既製部品の組み合わせである。既製部品の組み合わせであっても、状態・props・キーボード挙動を確定させておかないと実装者が組み方を選べないため仕様を書く。 [derived]

**ソート・フィルタの条件は部品の内部状態である**（Issue #91 により 2026-10-04 追記）。`AssignmentMatrixProps` は変わらない。条件は保存せず、マトリクスの読み直し（画面が読み込み中の表示に切り替わって部品が外れる）とプールの切り替えでリセットされる。ただし、非表示のロール列と畳んだ属性列は例外で、画面（`MatrixScreen`）が `useMatrixHidden` で状態を持ち、`localStorage` に保存する（`hiddenController`。Issue #140 により 2026-10-07 追記。FR-3.6）。

| Role color（Issue #100 により 2026-10-04 追記） | ロールの背景色は装飾であり、色名を `aria-label`・`title` に出さない（列の識別はロール名で行う）。ロール一覧の見本は `aria-hidden` で、色名は文字で出す。色のある列のヘッダは、パレットの背景の上で文字のコントラスト 4.5:1 以上を保つため、文字を濃い色（`#000716`）、補助文字を `#414d5c` に替え（差分記号はセルが既定の背景なので既定の色のまま。Issue #105 により 2026-10-04 訂正。訂正前は `#025a09` / `#a30f0f` に替える）、未反映の申請のチップは白い小さな囲みの中に置く |
| Label / aria-label | 各セルの checkbox に `aria-label="<userName> に <roleName> を割り当てる"`。列ヘッダの checkbox に `aria-label="<roleName> を申請対象に含める"`。除外チップに `aria-label="<roleName>: <理由>のため申請対象外"` |
