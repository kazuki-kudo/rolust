# 多言語対応（日本語・英語）設計

- Issue: #94
- 日付: 2026-10-14
- 対象: 管理画面（`packages/web`）と、SPA に届く API のエラー文言（`packages/core`・`packages/api`）
- 経路: アーキテクチャ級（画面の全体、API の応答の形、`docs/design/` にまたがる）。設計はチャットで 3 節に分けて承認済み（2026-10-14）。

## 1. 背景と目的

管理画面の文言は日本語の直書きで、日本語を読めない利用者は使えない。API のエラー本文も日本語で組み立てられ、`ErrorPanel` が `error.message` をそのまま出す。

目的は、利用者が画面の操作とエラー表示を英語で完結できることである。言語は利用者が選べ、既存の日本語の動作は変えない。

## 2. 決定事項

| # | 決定 | 理由 |
|---|---|---|
| 1 | 対象は SPA と、SPA に届く API のエラー文言。edge-auth の応答・ログ、README、`docs/design/`、`TABLE-DESIGN.md` の英訳は対象外 | 依頼者の判断（2026-10-14）。正本は日本語のままにし、二重管理を持たない |
| 2 | API は文言ではなく `localized: { id, params }`（`id` と、その `id` の `params` の型が対応する判別共用体）を返し、SPA が訳す。`message`（日本語）と `code` は従来どおり返す | 依頼者の判断。言語を知るのは SPA だけにする。`message` は旧版の SPA・ログ・既存テストとの互換 |
| 3 | 言語は `navigator.languages` の先頭が `ja*` なら日本語、それ以外は英語。画面内の切替で変えたら localStorage（`rolust.locale`）に保存し、保存値を優先する。サーバ側の利用者設定は持たない | 依頼者の判断。#140 の非表示列と同じく、表示の好みはブラウザに置く |
| 4 | 翻訳は自前の型付きカタログ（`ja.ts`・`en.ts`）。ライブラリを入れない。型の正本は `ja`（`typeof ja`）で、`en` の欠落・余分は `tsc` が落とす（api・core のエラーのカタログでは、ID と引数の型の正本は `ErrorMessageParams`） | 依頼者の判断（案 A）。2 言語だけで、キー欠落の検査を別に持たずに済む。依存を増やさないので npm audit の対象も増えない |
| 5 | 埋め込み値と単数・複数は、カタログの関数で書く（例: `deleted: (name) => …`） | 語順と複数形が言語で変わるため、連結では訳せない |
| 6 | エラーカタログ（`ErrorMessageId`・`ErrorMessageParams`・ja・en）は `core` に置く | エラー文言は API と SPA をまたぐ契約。ID と引数の型を両側で共有でき、片側の追加・削除が型エラーになる |
| 7 | `core` が `ja` で描画した文を `message` に詰める。`message` を持つすべての応答（エラー本文のほか、200 応答の反映結果・差分の読み取り失敗・取り消しの失敗・申請作成の失敗・警告）に同じ組を添える（決定 18） | ログ・旧版 SPA・既存テストが日本語の文を見続ける |
| 8 | SPA に届くエラー（`ApiError` 系・`ValidationError` など）のコンストラクタは `{ id, params }` を受け、生の文字列を受けない | 生の文字列を `tsc` で拒否し、直書きの復活を防ぐ。`api` 全体への日本語リテラル禁止は、運用ログ・移行 CLI が多く広すぎるので採らない |
| 9 | `ConfigurationError` と移行 CLI、運用ログは文字列のまま（対象外） | 運用者が CloudWatch で読むもので、利用者の画面には出ない。SPA は 500 に対し、`code` を添えた定型文で受ける |
| 10 | AWS SDK の例外メッセージ（`awsErrorMessage`）は訳さず、引数 `detail` として埋め込む | AWS が返す英語の文で、GI-6 の「AWS のコードを併記する」の対象。訳すと情報が落ちる |
| 11 | `ForbiddenError` の権限名は `need` を引数にし、言語別の権限名をカタログに持つ（`PERMISSION_LABELS` は `ja` の描画で使う） | 権限名が言語で変わるため |
| 12 | SPA は `localized` があればカタログで訳す。無ければ、5xx は言語別の定型文（決定 9）、それ以外（旧 API など）は `message` を出す。コードの併記（GI-6）は変えない | 反映の順序（§ 5）で、API が先に更新された状態と SPA が先に更新された状態の両方が成立するため |
| 13 | `formatTimestamp` の固定書式は変えない。並べ替えも UI の言語に依存させない | 日時は言語に依らない書式。`localeCompare` の対象は IAM 識別子（アカウント ID・ロール名・ISO 日時）で、文字種が ASCII に制約されるため、言語で順序が変わらない |
| 14 | Cloudscape の `I18nProvider` に、同梱の `all.ja`・`all.en` を言語に合わせて渡す。`<html lang>` と `document.title` も言語の変更に追従する | コンポーネントの ARIA ラベルなどが同じ言語になる |
| 15 | `useT()` の Context の既定値は `ja` のカタログにする | Provider なしで描画する既存の SPA テストが、`navigator.language` が `en-US` の jsdom でも変わらず通る |
| 16 | `packages/web/src` に、文字列リテラルとテンプレートの日本語を禁じる ESLint の規則（`no-restricted-syntax`）を入れる。`i18n/messages/ja.ts` とテストは除外 | 日本語の直書きの復活を lint で止める |
| 17 | 言語切替の UI は、全画面の文言の移行が終わってから出す | 途中の中途半端な英語を利用者に見せない |
| 18 | 200 応答に入る文言（`ApplyReport.message`・`warnings`、`DiffView.readError`、取り消しと申請作成の `failures[]`、`DiscardResponse.lockWarning`）も、`localized`（`warnings` は同じ並びの `localizedWarnings`）を添える。保存する反映結果（`ChangeRequest.result`）にも任意属性 `localized` を足し、旧レコードは `message` のまま表示する | 依頼者の判断（2026-10-15）。申請履歴の「反映結果」も英語で完結させる。DynamoDB はスキーマレスで任意属性の追加に移行は要らない。`TABLE-DESIGN.md` に属性を追記する（§ 7） |

## 3. 構成

### 3.1 core と api（PR 1）

- `core` に `ErrorMessageId`（例: `"arn.invalidUserArn"`）と `ErrorMessageParams`（ID から引数の型への写像）を置く。カタログは `errorMessages.ja` と `errorMessages.en` で、同じ型を実装する。`renderMessage(locale, message)` が文を返す（SPA は、知らない ID・壊れた引数を `null` にする `tryRenderMessage` を使う）。
- `RolustError`・`ApiError`・`ValidationError` などは `{ id, params }` を受け、`message` に `ja` の描画を詰める。`localized: { id, params }` を持つ。
- 約 107 か所の throw（`api/src`・`core/src`）と、200 応答に入る文言（決定 18）を `{ id, params }` へ置き換える。値を埋め込む箇所は `params` に分け、一覧を連結した文（削除できない理由など）は構造化した `params` にしてカタログ側で組み立てる。入れ子の文（CSV の行のエラーなど）は `params` に `LocalizedMessage` を持たせる。
- 運用者向けの文字列（移行 CLI の `batchGetAllWith` など）は、`operator.plain`（ja・en ともに `text` をそのまま出す）で包む。SPA に届くエラーには使わない。
- 応答本文は `{ code, message, localized?, field?, retryable }`（`ApiErrorBody` を拡張）。未処理の例外の 500 も ID を持つ。
- `toErrorResponse` は、`RolustError` の `localized` を本文へ載せる。api の `ErrorBody.localized` は必須、core の契約 `ApiErrorBody.localized` は（古い API の応答を受けるため）省略可のまま。`ConfigurationError` だけは、日本語の運用者向けの文が SPA に出ないよう、本文の `localized` を `server.internal` にする（`message` には設定不備の文を残す）。

### 3.2 web（PR 2）

- `packages/web/src/i18n/`: `messages/{ja,en}.ts`（画面・部品ごとの入れ子）、`locale.ts`（`detectLocale`・保存）、`LocaleProvider.tsx`（`useT()`・`useLocale()`・`<html lang>`・`document.title`・`I18nProvider`）。
- `AppShell` のヘッダの右側に、言語切替（`ButtonDropdown`。選択肢は「日本語」「English」で、各言語の表記）を置く。
- `labels.ts`・`history-filter.ts`・`matrix-hidden.ts`・`routes.ts`・`pool-view.ts`・`role-column-title.ts` と各 hook の日本語は、`Messages` を引数に取る関数へ移す。
- `ErrorPanel` は `describeError(t, error)` で本文を決める。`ApiClientError` の既定文言（「API 呼び出しに失敗しました」「サーバに接続できませんでした」）は SPA のカタログへ移し、`localized` を持たない応答の既定として描画する。
- `index.html` の `lang="ja"` と `<title>` は初期値として残し、起動時に `LocaleProvider` が言語に合わせて書き換える。

## 4. テスト方針（TDD）

- **SPA**: 既存のテストは書き換えない（決定 15）。足すテスト:
  - `detectLocale`（保存値の優先、`ja*` の判定、不正な保存値の無視）。
  - `LocaleProvider`（localStorage が使えないとき、`lang` と `title` の更新、`I18nProvider` に渡すメッセージ）。
  - 言語切替（`AppShell`）。
  - 各画面に英語のスモーク 1 本（見出し・主ボタン・完了通知。埋め込み値と単数・複数を含める）。
  - `describeError`（`localized` がある場合と、無い場合の `message` へのフォールバック）。
  - カタログの検査（`en` に日本語の文字が残っていない）。
- **core・api**: 既存テストは `message` を日本語で検証しているので、`ja` の描画が従来と同じ文であることの回帰になる。足すのは、各エラーの `localized`（`id`・`params`）の検証と、応答本文の形のテスト。
- **機械的な検査**: キー欠落は `tsc`、日本語の直書きの復活は ESLint（決定 16）、生の文字列のエラーは `tsc`（決定 8）。
- **実 AWS を要する検証**: 本番の画面と API で実測する（§ 5）。モックでは、CloudFront と Cognito を通した表示・保存は確かめられない。

## 5. 反映の順序と戻し方

1. PR 1（core・api）を merge し、Lambda（crud・diff・apply）を README の手順で反映する。応答は互換なので、現行の SPA は影響を受けない。API に不正な入力を送り、`localized`・日本語の `message`・`code` が返ることを実測する。反映の結果が `localized` つきで保存されることは、検証用ロールでの反映（`verification-needs-temp-role` の手順）で実測する。
2. PR 2（web）を merge し、SPA を反映する。Cognito の検証専用ユーザで本番に入り、ヘッドレス Playwright で次を実測する。終わったら検証ユーザを削除する。
   - 言語切替で全画面が英語になる。
   - 不正な入力による API エラーが、英語の本文とコードの併記で出る。
   - `<html lang>` と `document.title` が切り替わる。
   - ブラウザの言語が `ja` のときの初期言語、localStorage の保存の再現。
3. 戻し方: SPA は直前の版へ戻す（`rollback-runbook.md` の SPA の手順）。API の拡張は互換なので戻さなくてよい。

`cd.yml` は反映しない（`cd-config.md` D-7）。反映と実測は plan の最終タスクに含める。

## 6. 範囲外

- 英語以外の言語。3 言語目が必要になれば、ICU 形式のライブラリを入れるかを見直す。
- edge-auth の応答・ログ、README・`docs/design/`・`TABLE-DESIGN.md` の英訳。
- サーバ側の利用者設定（言語の保存）。#20 の Cognito でユーザごとの設定が要る場面が出たら別に決める。
- 日時の書式のロケール化。
