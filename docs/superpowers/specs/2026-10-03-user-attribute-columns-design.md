# IAM ユーザに属性列を持たせる — 設計

- 日付: 2026-10-03
- Issue: #61
- ブランチ: `feat/61-user-attribute-columns`
- 状態: spec レビュー待ち

## 1. 背景と目的

ユーザプールの IAM ユーザには、`poolId` / `accountId` / `userName` / `arn` / `createdAt` しか属性が無い（`packages/core/src/types.ts` の `IamUser`）。誰のユーザか（名前・役割・部署など）を Rolust に残す場所が無く、マトリクスで ARN だけを見て割り当てを決めることになる。

Issue #61 は、IAM ユーザごとに属性列を持たせ、列名を利用者が変えられるようにし、CSV で属性ごと一括登録できるようにする要望である。概要のみのヒアリングに基づくため、範囲は着手時に決める旨が Issue に書かれている。依頼者は 2026-10-03 に、**属性列を #61 で実施し、CSV の一括登録は別 Issue に分ける**ことを選んだ。CSV の仕様（ヘッダ行の有無・重複・一部の行の失敗）は、属性の形が実装で固まってから決めるほうが手戻りが少ない。

### 成功基準

1. ユーザプールごとに属性列（最大 10 列）を追加・名前変更・削除でき、結果が一覧に出る。
2. IAM ユーザごとに、列ごとの値（0〜128 文字）を設定・変更・解除できる。
3. 列の名前を変えても、既存の値は残る。列を削除すると、その列の値は読み取りで現れず、同じ名前で作り直しても復活しない。
4. 属性は IamUser の識別（ARN）・Assignment・ChangeRequest の凍結入力に影響しない。差分確認・反映の挙動は変わらない。
5. IAM ポリシー（`infra/`）を変えない。
6. 実 DynamoDB で、属性の保存・名前変更後の値の保持・列の削除後の読み取りを実測する（3.6）。

## 3. 設計

### 3.1 データモデル（`packages/core`）

- `UserPool` に `attributeColumns: AttributeColumn[]` を足す。`AttributeColumn` は `{ columnId: string; name: string }`。未設定のプールは空配列。
- `IamUser` に `attributes: Record<string, string>` を足す。値が空のものは持たない。
- `packages/core/src/attribute.ts`（新規）に、純粋な検証と正規化を置く。
  - `normalizeColumnName(name)`: D-7 の規則。違反は例外ではなく、既存の `normalizeRoleDescription` に合わせた形で理由を返す。
  - `normalizeAttributeValue(value)`: D-8 の規則。空は `null`。
  - `validateColumns(columns)`: 10 列以下、列名の一意。
  - `pruneAttributes(attributes, columns)`: 定義に無い `columnId` の値を落とす（D-6）。

### 3.2 API（`packages/api`）

どちらも CRUD 系統で、AWS は呼ばない。ハンドラは `handlers/pools.ts` に足し、処理は `services/` に置く。

**`PUT /pools/:poolId/attribute-columns`**

- body: `{ columns: [{ columnId?: string, name: string }] }`
- 検証: 3.1。10 列超過・列名の重複・列名の規則違反・知らない `columnId` は 400。プールが無ければ 404。
- 新規の列（`columnId` なし）に採番する。応答は保存後の `columns`。
- META アイテムへの UpdateItem（`attribute_exists(pk)`）。`attributeColumns` は丸ごと置き換える。

**`PUT /pools/:poolId/users/attributes?arn=<userArn>`**

- body: `{ attributes: { [columnId]: string } }`
- 検証: ユーザの ARN・プールの存在・ユーザの存在（無ければ 404）、定義に無い `columnId` は 400、値は D-8 に従って正規化する。
- 属性を、空でない値だけの `attributes` マップとして丸ごと置き換える。**`SET attributes.#id` のような入れ子のパスは使わない**。親のマップが無いアイテムでは実 DynamoDB が拒否し、モックは受理しうるため。`SET attributes = :map`（空なら `REMOVE attributes`）とする。条件は `attribute_exists(pk)`。
- 応答は保存後のユーザ。

**一覧の取得**（既存の `GET /pools` ほか `PoolView`）は、列定義とユーザの `attributes` を含める。読み取りで、定義に無い `columnId` の値を落とす（D-6）。`packages/core/src/api-contract.ts` と `packages/web/src/api-client.ts` に型と呼び出しを足す。

### 3.3 テーブル設計（`packages/api/TABLE-DESIGN.md`）

キーは変えない。UserPool の META に `attributeColumns`、IamUser のアイテムに `attributes` を足す。アクセスパターンを足す。

| # | 用途 | 操作 |
|---|---|---|
| 23 | 属性列の定義の保存 | UpdateItem `pk = POOL#<id>`, `sk = META`（`attribute_exists(pk)`）。`attributeColumns` を置き換える |
| 24 | ユーザの属性の保存 | UpdateItem `pk = POOL#<id>`, `sk = USER#<userArn>`（`attribute_exists(pk)`）。`attributes` を丸ごと置き換える（空なら REMOVE） |

NFR-2 との対応: 列定義は最大 10 件の小さな配列で、件数に比例して肥大しない。ユーザの属性は IamUser 1 件 = 1 アイテムの中に収まる（最大 10 値 × 128 文字）。`Scan` は使わない。

### 3.4 画面（`packages/web`、画面 1）

- `PoolsScreen` の IAM ユーザ表は、属性列が 0 件のプールでは今のまま（アカウント ID ごとに 1 行）。1 件以上あるプールでは 1 ユーザ 1 行の表に切り替え（D-12）、「AWS アカウント」「IAM ユーザ名」の後ろに属性列を追加順に出し、右端に「属性を編集」「削除」を置く。値が無いセルは「—」。
- プール単位の操作に「属性列を編集」を「このプールにユーザを登録」の次に足す。モーダルで、列の追加・名前変更・削除をする。列の削除では、値が見えなくなることを示す。入力の検証は 3.1 と同じ関数をエラー文言につなぐ。
- 行の操作に「属性を編集」を足す。モーダルに、列ごとの入力欄を出す。「属性を編集」は 1 ユーザ 1 行の表（属性列が 1 件以上、D-12）にしか出ないので、列が 0 件のモーダルは作らない。
- どちらも `GuardedModal`（GI-4: 入力があれば破棄確認）に載せ、保存中のラベルは進行形（GI-7）にする。保存の失敗はモーダル内に出す。
- 利用者に見える文言に要件 ID を入れない（#95 の機械判定）。

### 3.5 テスト

- 4 パッケージの TDD。失敗するテストを先に書く。
  - core: `attribute.ts` の検証・正規化・`pruneAttributes`。
  - api: 列定義の保存（採番・上限・重複・知らない ID）、ユーザの属性の保存（定義に無い列・値の正規化・丸ごと置き換え）、一覧の読み取りの `pruneAttributes`、ハンドラの 400・404。
  - web: 一覧の属性列の表示、2 つのモーダルの操作・検証・破棄確認・保存の失敗。
- モックの限界: `SET attributes = :map` は実 DynamoDB でしか確かめられない。3.6 で実測する。

### 3.6 反映と実測（plan の最後のタスク）

CD は反映しない（`docs/design/cd-config.md` D-7）。README の手順で、デプロイ先へ反映する（Lambda のコードと SPA だけ。`infra/` は変えない）。実測は、依頼者も同時に本番を触るので、検証用のプールを新規作成して行い、終わったら DynamoDB の登録を消す。

1. 属性列を 2 つ作り、ユーザに値を入れて、一覧に出る。
2. 列名を変えて、値が残る。
3. 列を削除して、値が読み取りに出ない。同じ名前で作り直しても復活しない。
4. 属性の保存の前後で、IAM（`UpdateAssumeRolePolicy`）が呼ばれない。CloudTrail は us-east-1 に `AttributeKey=EventName` で引く。

### 3.7 範囲の外

- CSV の一括登録（別 Issue）。
- マトリクス・申請・履歴への属性の表示（#91 の brainstorming で決める）。
- 列の並べ替え、属性による並べ替え・絞り込み。
- 値の型（数値・選択肢など）。すべて文字列。
