# IAM ロールの表示名と、割り当てマトリクスでの優先表示（Issue #150）

日付: 2026-10-08 / 関連: #21（説明。同じ形の属性）・#100・#105（列ヘッダの色）・#108（ユーザプールの表示名の廃止）・#135（登録＝紐づけ）・#140（列の非表示）・#145（申請 ID 列）

## 1. 目的と背景

IAM ロールには正式なロール名しか無い。割り当てマトリクスでは、長い・似た名前のロールを見分けにくい。ロールに任意の表示名を持たせ、マトリクスの列では表示名を優先して見せる。

目的は 2 つ。

1. IAM ロールに任意の表示名を設定・変更・解除できるようにする（未設定なら従来どおり正式なロール名）。
2. 割り当てマトリクスの列で、表示名を優先して表示し、ホバーで正式なロール名を確かめられるようにする。

表示名は Rolust の管理情報であり、IAM 側のロール名・タグ・信頼ポリシーは変えない。AWS を呼ばず、ChangeRequest も生成しない。

### 受け入れの観点（Issue #150 の受け入れ条件）

- 表示名を登録・変更・解除できる（API テストと画面のテスト）。
- 表示名が無いロールは、従来どおり正式なロール名が出る（回帰テスト）。
- 表示名があるロールは、マトリクスの列ヘッダで表示名が出る（画面のテスト）。
- 表示名にホバーすると、正式なロール名が出る（画面のテスト）。
- IAM 側のロールは変わらない（既存の「AWS へ書き込まない」テストの範囲を、表示名の保存に広げる）。

## 2. 決定

| ID | 論点 | 決定 | 根拠 |
|---|---|---|---|
| D-1 | 永続化 | `IamRole` のアイテムに任意の `displayName` 属性を足す。キーは変えず、移行は無い | 導出: 説明（#21）と色（#100）が同じ形で `IamRole` の属性になっている。別アイテム（B 案）は一覧の Query と書き込みが増え、説明の形から外れるので採らない |
| D-2 | 設定場所 | 画面 2（IAM ロール管理）の登録モーダルに任意の欄を足し、一覧行の「編集」モーダルで変更・解除する。編集モーダルは説明と表示名の 2 欄にする | 導出: FR-7.2 が、ロールの属性（説明・色）の編集を画面 2 に置いている。説明と表示名を 1 つのモーダルにまとめ、ロールの表示の設定を 1 か所にする |
| D-3 | 文字数上限 | 前後の空白を除いて 1〜32 文字（コードポイント数で数える） | 依頼者の決定（2026-10-08）。日本語は全角で、マトリクスのヘッダ（幅は `minWidth` 12rem、`maxWidth` なし）に折り返して収まる幅にする。32 文字は属性列名の上限（`ATTRIBUTE_COLUMN_NAME_MAX_LENGTH`）と揃える |
| D-4 | 文字の規則 | 制御文字（Cc・Zl・Zp）は不可。見える文字（Cf と空白以外）が無ければ不可。空なら未設定。説明（`normalizeRoleDescription`）と同じ規則 | 導出: 説明と同じ入力検証（#21・#33） |
| D-5 | 重複 | 登録済みロールの間で、表示名の重複を拒否する。比較は前後の空白を除いた後の完全一致（大文字小文字を区別する） | 導出: プール内の属性列名は重複を拒否している（`AttributeColumnsModal`）。マトリクスで列を区別するのは名前なので、同じ表示名が並ぶと見分けの目的に反する。正式名はホバーで出るので、拒否しても識別は残る |
| D-6 | 重複の検査の競合 | 同時に同じ表示名を保存したときの競合は排他しない（両方が通ることがある） | 導出: 排他は ChangeRequest の状態遷移だけ（FR-5.8・Issue #121）。表示名は管理者が後から直せる、表示だけの値で、競合の確率は低い |
| D-7 | 解除 | 空（前後の空白だけを含む）で保存すると未設定に戻す。別の削除操作は作らない | 導出: 説明と同じ |
| D-8 | 表示名の入力の拒否の文言 | 「表示名は 32 文字以内で入力してください」「表示名に制御文字(改行・タブなど)は使えません」「表示名に見える文字がありません」「表示名「…」は、ほかのロールで使われています」 | 導出: 説明の文言（#21）に揃える。「ユーザプールの表示名」（#108 で廃止）と区別するため、文言の主語は「表示名」だけにせず、ロールの表示名であることが分かるよう画面の欄の見出しを「ロールの表示名」にする |
| D-9 | 一覧 | 画面 2 の一覧に「表示名」列を足す（未設定は「—」） | 導出: 説明の列と同じ形 |
| D-10 | マトリクスの列の名前 | 列ヘッダの名前・列メニューの `aria-label`・申請に含めるロールの選択欄は、表示名（未設定なら正式名）を出す | Issue #150 の「列ヘッダ（ロール名）は表示名を優先」。列メニューと選択欄は同じ列を指すので、ヘッダと同じ名前にそろえる |
| D-11 | マトリクスのホバー（ツールチップ） | 表示名がある列は、`title` に「正式なロール名」を 1 行目、説明があれば 2 行目に出す。表示名が無い列は、今の挙動（説明があれば説明）のまま | Issue #150 の「表示名にマウスを当てたら、正式なロール名をツールチップで表示」。説明の表示を失わないため 2 行目に残す |
| D-12 | 申請・差分・履歴・除外の帯の文言 | 変えない。正式なロール名のまま | 導出: これらは AWS 上の対象を指す文言で、ARN と対応させる必要がある。Issue の範囲（マトリクス）の外（申請履歴・申請詳細は範囲外） |
| D-13 | 列の折り返し | ヘッダは表示名を折り返して全部見せる（省略記号で切らない）。英数字だけの長い名前に備えて、ヘッダに `overflowWrap: "anywhere"` を足す | 導出: 切り詰めると、ホバーの正式名だけになり、表示名の全体が読めなくなる。32 文字でも英数字だけなら列幅を超えうる。見え方は実装時に画面で実測して確かめる |
| D-14 | 文言 | 画面の欄の見出しと説明文は「ロールの表示名」と書く。コードの識別子は `displayName`・`roleDisplayName` とし、ユーザプールの表示名（#108 で廃止）と混同しない | Issue #150 の「ユーザプールの表示名とは別の概念であることを画面文言で区別する」 |

## 3. 設計

### 3.1 ドメイン（`packages/core`）

`packages/core/src/role.ts` に、`normalizeRoleDescription` と同じ形で追加する。

```ts
/** 表示名の上限（D-3）。コードポイントで数える。 */
export const ROLE_DISPLAY_NAME_MAX_LENGTH = 32;

/** 表示名を正規化する。前後の空白を除き、空なら `null`（未設定）。`field: "displayName"` の ValidationError を投げる。 */
export function normalizeRoleDisplayName(value: string | null | undefined): string | null;
```

- 制御文字・見える文字・上限の規則は説明と同じ（D-4）。文言だけ D-8 のとおり。
- 重複の検査は core に置かない（登録済みの一覧が要るため、API の service で行う）。
- `types.ts` の `IamRole` に `displayName: string | null` を足す（説明と同じ注記の形）。

### 3.2 API（`packages/api`）

| 操作 | 変更 |
|---|---|
| `POST /roles` | 任意の `displayName` を受ける。検証は書式 → 重複の順。登録の書き込み（`createRole` の PutItem）に含める |
| `GET /roles` | 各ロールの `displayName` を返す（`null` は未設定） |
| `PATCH /roles?arn=` | `displayName`（文字列・null）を受ける。`description`・`color` と同じく「少なくとも 1 つ」の規則に入れる。検証がすべて終わってから書く（既存の順序）。`displayName` が変わるときだけ重複を検査する |

- 重複の検査は、`listRoles()`（Query `pk = ROLE`）で登録済みの一覧を読み、自分以外の ARN で同じ表示名（trim 後の完全一致）があれば 409 相当で拒否する。拒否の種類は既存の `ConflictError` を使う。
- 永続化は `repository/role.ts` に `updateRoleDisplayName(roleArn, displayName)` を足す。`updateRoleDescription` と同じ形（`attribute_exists(pk)` の条件付き UpdateItem。SET と REMOVE を切り替える）。
- 新しいサービスは `packages/api/src/services/role-display-name-service.ts`（`role-description-service.ts` と同じ形）。
- `TABLE-DESIGN.md` の `IamRole` の属性に `displayName` を足し、アクセスパターン 5（一覧）・13（登録の PutItem）に表示名を足す。18 は「説明の更新」から「説明・表示名の更新」に改める。

### 3.3 画面 2（`packages/web/src/screens/RolesScreen.tsx`・`EditRoleDescriptionModal.tsx`）

- 登録モーダル: 任意の「ロールの表示名」欄を足す（説明の欄の前）。検証は blur と送信時（GI-1）。
- 一覧: 「表示名」列を足す（D-9）。
- 一覧行の「編集」モーダル（`EditRoleDescriptionModal`）: 「ロールの表示名」と「説明」の 2 欄にする（D-2）。保存は、変わった方だけを PATCH で送る（既存の `dirty` 判定を流用）。
- 表示名の重複の拒否（409）は、編集モーダルでは表示名の欄の下、登録モーダルでは重複と「既に登録」を区別できないためフォーム全体に出す（D-8。Issue #150 の最終レビューにより 2026-10-08 訂正。訂正前は「欄の下にエラーとして出す」）。

### 3.4 画面 3（`packages/web/src/components/AssignmentMatrix.tsx`・`MatrixGrid.tsx`）

- `AssignmentMatrix.tsx` で列に渡す値に `displayName` を足す（`description` と並べる）。
- `MatrixGrid.tsx` の列ヘッダ: 表示する名前は `displayName ?? roleName`（D-10）。列メニューの `aria-label` も同じ名前を使う。
- ツールチップ（D-11）: 表示名がある列は `title` を「`roleName`」＋（説明があれば）改行と説明にする。表示名が無い列は、今の `title = description` を変えない。
- ヘッダの折り返し（D-13）: `overflowWrap: "anywhere"` を足す。列の幅は今の `minWidth` を変えない。
- 申請に含めるロールの選択欄（D-10）も同じ名前を使う。

### 3.5 変えないもの

- 申請の確認・差分・履歴・申請詳細・除外の帯の文言（D-12）。
- 信頼ポリシーの反映・ChangeRequest・Assignment の保存（表示名は読み替えだけ）。
- 権限（`requires: "edit"` を PATCH・POST に既存どおり適用する。表示名の保存に viewer は書けない）。

## 5. テスト方針

TDD（CLAUDE.md。アプリコードは失敗するテストを先に書く）。

- `packages/core`: `normalizeRoleDisplayName` の単体テスト（空・空白のみ→null、前後の空白の除去、32 文字の境界（日本語 32 文字は通り、33 文字は拒否）、制御文字、見える文字の無い名前、`field`）。
- `packages/api`:
  - `role-display-name-service.test.ts`: 保存・解除、重複の拒否（自分自身は除く）、存在しないロール（404）、変わらない値では書かない。

  - `handlers/roles.test.ts`: `POST /roles` の displayName（不正な型・重複）、`PATCH /roles` の「少なくとも 1 つ」規則、`GET /roles` の displayName。
  - AWS へ書き込まないこと（IAM の mock が呼ばれない）。
- `packages/web`:
  - `RolesScreen`・`EditRoleDescriptionModal`: 登録と編集（2 欄・重複のエラー・解除）。
  - `MatrixGrid`・`AssignmentMatrix`: 表示名があるときのヘッダ・ツールチップ（正式名 + 説明）、表示名が無いときの従来の表示、列メニューの `aria-label`。
- 統合テストは不要。表示名は DynamoDB の属性だけで、IAM に触れない。

## 6. 反映と実測

- 反映: Lambda（API）と SPA を README の手順で本番へ反映する。Terraform の変更は見込まない（新しいリソースや変数が要らない）。反映後に `terraform plan` が差分ゼロであることを確かめる（CD の plan は反映しない。`docs/design/cd-config.md` D-7）。
- 実測（plan の最終タスク）: 本番で、表示名を登録・変更・解除し、マトリクスの列ヘッダ・ツールチップ・折り返しを画面で確かめる。表示名の登録・解除は、検証用の表示名（使い捨ての値）で行い、終わったら元の値（未設定）に戻す。既存のロールの表示名は変えない（既存の本番ロールの表示を変える場合は、依頼者の確認を取る）。
- 実測の手段は、画面の操作テストの手順（`browser-tests-with-basic-auth`・Playwright）に従う。

## 7. 範囲外

- 申請履歴・申請詳細・差分の表示名（D-12）。
- 表示名による検索や並べ替え（マトリクスの列の並び順は並び順（FR-2.6）のまま）。
- ユーザプールの表示名の復活（#108 で廃止したまま）。
- 表示名の変更の履歴（監査）。Rolust の管理情報で、監査の対象は割り当てと申請。
