# 割り当てマトリクスの列の非表示と、その状態の永続保存（Issue #140）

日付: 2026-10-07 / 関連: #91・#100・#104（保存しない決定）・#107（属性列の畳み）・#121（排他）・#135（登録＝紐づけ）・#141（権限）

## 1. 目的と背景

画面 3 の割り当てマトリクスには、ロール列を隠す操作が無い。属性列は畳めるが、畳みは保存せず、読み直しでリセットされる。ロールが増えると、普段使わない列が常に場所を取り、読み直すたびに見た目を付け直すことになる。

目的は 2 つ。

1. ロール列を非表示にできるようにする。
2. 非表示のロール列と畳んだ属性列を、読み直しをまたいで保存する。

### 受け入れの観点

- ロール列を非表示・再表示でき、読み直し後も状態が残る（ユニットテスト）。
- 非表示のロール列の変更の扱いが、申請の内容と食い違わない（回帰テスト）。

## 2. 決定

| ID | 論点 | 決定 | 根拠 |
|---|---|---|---|
| D-1 | 保存先 | ブラウザの `localStorage`。API・DynamoDB・IAM・terraform は変えない | 依頼者の決定（2026-10-07）。表示の好みで、AWS にも他の管理者にも影響しない。サーバ保存は API・TABLE-DESIGN・Lambda の変更と本番反映が要り、割に合わない |
| D-2 | 状態の単位 | 管理者ごと（ブラウザごと） | 導出: プール単位の共有は、他の管理者の操作で自分の表示が変わる。#141 の viewer は書き込み権限を持たないので、サーバ保存だと viewer だけ保存できない設計判断も生じる。localStorage なら権限に依らない |
| D-3 | キー | `rolust:matrix-hidden:v1:<識別子>`。識別子は `GET /me` の `actor.sub`、無ければ `actor.name`（`auth_mode=basic`）。どちらも読めない間（権限の読み込み中）は読み書きしない | `sub` は変わらない ID（`Actor` の定義）。同じブラウザを複数の管理者が使っても混ざらない。プール ID はキーに含めない（プールは固定の 1 つ。#108） |
| D-4 | 保存するもの | 非表示のロール ARN の集合と、畳んだ属性列の `columnId` の集合だけ | Issue の論点。ソート・フィルタ・絞り込み欄・並び順は保存しない。#91・#100・#104 の「保存しない」決定を覆さない |
| D-5 | 隠したロールの変更の扱い | **選択中のロールは隠せない**（不変条件: 申請に含める選択中の列は必ず表示されている）。隠すときの選択は変えない（隠せないので、そもそも選択中の列は隠す操作ができない） | 導出: 申請の対象は利用者が列で明示した選択だけ（`selectedRoleArns`）。選択中が常に見えていれば、隠れた列の変更が申請に入ることはない。選択を黙って外す案は、見えない所で選択が変わるので採らない |
| D-6 | 隠れた変更の可視化 | 件数の行に「非表示 n 列」を出し、非表示の列に変更があるときは「（変更あり m 列）」を添える。変更の無い非表示列は添えない | 変更のある列を隠したまま忘れるのを防ぐ。ただし申請には入らないので、警告ではなく情報として出す |
| D-7 | 隠せるロール | 選択中でないすべてのロール。除外（FR-4.6）中の列も隠せる | 除外中の列は選択できず、申請に入らない。除外の帯（ExclusionBanner）は列の表示に依らず出し続ける |
| D-8 | 非表示の入口と再表示 | 入口: ロール列の「▾」メニューに「この列を隠す」。再表示: 件数の行の「非表示 n 列」ボタンが開く一覧（ロール名ごとの「表示する」と「すべて表示」） | Issue の論点。既存のメニューと件数の行を使い、新しいコンポーネントを増やさない |
| D-9 | 古くなった状態 | 読み込むとき、現在の列（ロール ARN・属性の `columnId`）に無い値を捨てる。捨てた結果は次の保存で書く。新しく増えたロール（#135）は非表示ではない | 導出: 登録解除・削除されたロールや属性列の残骸が、再登録のときに復活して隠れた列になるのを防ぐ |
| D-10 | 保存の失敗 | `localStorage` が使えない・壊れた JSON のときは、保存しないだけで画面は動かす（読み込みは空の状態）。握りつぶさず `console.warn` に残す | 統合境界のエラー処理（CLAUDE.md）。表示の好みなので、画面を止めるほどではない |
| D-11 | 条件の絞り込みとの関係 | 非表示のロール列に付いたフィルタ・ソートは有効のまま残す（隠した列で絞り込みが効き続ける）。ただし再表示の一覧（D-8）で、条件のある非表示ロールに「（条件あり）」を添える | 導出: 隠すことと条件を外すことは別の操作。条件を黙って外すと、行が突然増える。見えない列で行が絞られていることは、一覧で気づける |
| D-12 | 属性列の畳み | 既存の畳み（#107）の状態を同じキーに保存する。畳み・開きの挙動は変えない | Issue の目的 2 |
| D-13 | 自動選択（DF-4）との関係 | 変更件数が 0 → 1 になった列の自動選択は、非表示のロールを対象にしない。非表示のロールを再表示しても、自動では選択しない（選ぶのは利用者） | 実装の調査で判明（`MatrixScreen` の preselect は、読み込み直しのたびに「変更のあるロールすべて」を 0 → 1 とみなして選択する）。除外しないと、読み込み直しで隠した列が選択されたまま見えなくなり、D-5 の不変条件が破れる。導出: 不変条件を満たす最小の手当て |

D-11 の補足: 隠した列に条件がある状態は、件数の行の「すべて解除」で外せる。

## 3. 設計

### 3.1 保存する値（`packages/web/src/matrix-hidden.ts`・新規）

純粋な関数と型だけを持つ。React に依存しない。

```ts
export interface MatrixHidden {
  roleArns: ReadonlySet<string>; // 非表示のロール
  foldedColumnIds: ReadonlySet<string>; // 畳んだ属性列
}
export const EMPTY_HIDDEN: MatrixHidden;
export function hiddenKey(identity: string): string; // rolust:matrix-hidden:v1:<identity>
export function loadHidden(storage: Pick<Storage, "getItem">, identity: string): MatrixHidden;
export function saveHidden(storage: Pick<Storage, "setItem">, identity: string, hidden: MatrixHidden): void;
export function pruneHidden(hidden: MatrixHidden, roleArns: Iterable<string>, columnIds: Iterable<string>): MatrixHidden;
export function canHideRole(roleArn: string, selected: ReadonlySet<string>): boolean;
```

保存形式は `{"roleArns": string[], "foldedColumnIds": string[]}`（配列は整列して書く）。`loadHidden` は不正な形・型の違う要素を捨てて空に倒す（D-10）。

### 3.2 `useMatrixHidden`（`packages/web/src/hooks/useMatrixHidden.ts`・新規）

識別子（`GET /me` の `actor`）を受け、`{ hidden, hideRole, showRole, showAllRoles, toggleFold }` を返す。識別子が決まるまでは空の状態を返し、保存しない（D-3）。状態が変わるたびに `saveHidden` する。`pruneHidden` は現在の列が分かったときに 1 回かけて、状態を整える（D-9）。

`AssignmentMatrix` が `folded` を内部の `useState` で持つ現状を、このフックの値へ置き換える。`AssignmentMatrixProps` には、非表示の状態を受ける props を足す（3.4）。

### 3.3 列の導出

`AssignmentMatrix` の `columns` から、非表示のロールを除いた列だけを `MatrixGrid` へ渡す。`MatrixGrid` は表示する列だけを描くので変えない（列が減るだけ）。

- `changeCounts`・`excluded`（除外の帯）・`selectableCount` は全ロール基準のまま（申請の件数と帯は列の表示に依らない。FR-3.3 の「列ごとの変更件数と選択は絞り込みの影響を受けない」と同じ考え方）。
- 非表示のロールにも `columnView`（フィルタ・ソート）は残る（D-11）。

### 3.4 UI

- ロール列の「▾」メニュー（`ColumnMenu`）に「この列を隠す」を足す。選択中のロールでは `aria-disabled` にし、理由「申請に含めている列は隠せません」を `aria-describedby` で結ぶ（`canHideRole`）。選ぶとメニューを閉じ、フォーカスを**隣の列**のヘッダへ移す（隠した列は DOM から消えるため。右隣が無ければ左隣。列がすべて隠れたら件数の行のボタンへ）。
- 件数の行に「非表示 n 列」ボタン（n ≥ 1 のときだけ）。押すと一覧のポップオーバーを開く。各行は「<ロール名>」（変更があれば「（変更あり）」、フィルタ・ソートがあれば「（条件あり）」を添える）と「表示する」ボタン、末尾に「すべて表示」。Escape で閉じてボタンへ戻す。変更の無い非表示ロールは「（変更あり）」を付けない（D-6）。
- すべての列が非表示になったときは、本体に「すべての列を隠しています」と「すべて表示」を出す（no-match と同じ形。ヘッダと件数の行は残す）。
- キーボード・読み上げ: 隠した列はローミング tabindex の対象から外れる（DOM に無い）。Tab 停止点は 1 つのまま。ボタンの `aria-label` は「非表示の列 n 件を表示する一覧を開く」とし、件数の変化は `aria-live="polite"` の領域で「<ロール名> の列を隠しました」と告げる。

### 3.5 申請との関係（D-5 の検証）

`MatrixScreen` の `selectedRoleArns` と `createChangeRequests({ roleArns })` は変えない。回帰テストで次を守る。

- 選択中のロールは `canHideRole` が偽で、隠す操作ができない。
- ロールを隠しても `selectedRoleArns` は変わらない。
- 変更のある非表示ロールは、選択していなければ申請に入らない。選択してから隠せない。
- 非表示ロールを再表示しても選択状態は変わらない。
- 画面を読み込み直した（再マウントした）とき、変更のある非表示ロールは自動選択されない（D-13）。
