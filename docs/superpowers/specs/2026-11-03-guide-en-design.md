# 手順書 2 本の英語版と、見出しの整合検査（Issue #205）

## 意図

Rolust を OSS として公開する。英語圏の人にも使ってほしいので、最低限、導入の手順を英語で読めるようにする。現状は `docs/guide/` が日本語のみ（Issue #179 の決定）で、英語の README は流れだけを示して「詳細は日本語の手順書」と案内している。英語しか読めない人は、README の先で止まる。

依頼者の言葉: 「オープンソースとして公開するので英語圏の人にも使ってほしい。最低限インストールする手順ぐらいは英語で提供したい」。

## 決めたこと（依頼者の判断）

| 項目 | 決定 |
|---|---|
| 英語版を持つか | 持つ。Issue #179 の「`docs/guide/` は日本語のみ」を、2 本について覆す（Issue の選択肢 A） |
| 範囲 | `setup.md` と `access-control.md` の 2 本。`setup.md` が導入の手順の本体で、`access-control.md` は導入中の `auth_mode` の選択で必ず通る |
| 整合の検査 | 見出しの数と順序の一致を CI で検査する |

## 目標・非目標・やってはいけないこと

**目標**

- 英語しか読めない人が、tarball の入手から動作確認までを、英語の手順書だけで完了できる。
- 日本語版だけ更新されて英語版が古くなる事態のうち、構造のずれ（節の追加・削除・入れ替え・階層の変更）を機械で見つける。

**非目標**

- `docs/guide/` の残り 6 本（overview・cross-account・managed-roles・users・operations・limitations）の英訳。
- 見出しの文言、リンク、コードブロック、本文の訳の正しさの検査。これらはレビューで見る。
- README（2 本）の整合検査。今回は手順書だけを検査する。
- 管理画面の文言や API の挙動の変更。

**やってはいけないこと**

- 英語版を正本にしない。日本語が正本で、英語は日本語から訳す。
- 英訳していないページへのリンクを、存在しない英語版に向けない（リンク切れにしない）。
- 日本語版の内容を、英訳の都合で変えない。

## 設計

### 置き場所と運用規則

- `docs/guide/en/setup.md`、`docs/guide/en/access-control.md`。日本語版の `docs/guide/` 直下と同じファイル名で、相対リンクの構造を揃える。
- 運用は README と同じ。日本語が正本。この 2 本を変える PR は、日本語版と英語版を同じ PR で更新する。見出しの構造・順序を 1 対 1 に揃える。
- 英語版の冒頭に、日本語版へのリンク（`**English** | [日本語](../setup.md)`）を置く。日本語版の冒頭にも対の行（`[English](en/setup.md) | **日本語**`）を足す。README の言語切替と同じ書式。
- 英訳していないページへのリンクは、日本語版のページに向け（`../limitations.md` など）、リンク文言の直後に「(Japanese)」を添える。英訳済みの 2 本どうしは、英語版どうしでリンクする。
- 日本語の節名を指す固定アンカー（`operations.md#設定ファイルを紛失したとき` など）は、そのまま日本語のアンカーに向ける。

### 見出しの整合検査

- スクリプト `.github/scripts/guide-parity.sh` を足す。`docs/guide/en/*.md` の各ファイルについて、同名の `docs/guide/*.md` と、**見出しの階層の列**（`#` の数を、出現順に並べたもの）を比べる。違えば、ファイル名と、最初に食い違う位置（何番目の見出しか）を出して終了コード 1 で止まる。値（本文）は出さない。
- フェンス付きコードブロック（```` ``` ````）の中の `#` で始まる行（シェルのコメント）は、見出しに数えない。手順書の bash のコメントが、これにあたる。
- `docs/guide/en/` に、対応する日本語版が無いファイルがあれば落ちる。日本語版があるのに英語版が無いファイルは、検査しない（英訳しないページが正常なため）。
- 文言の一致は見ない。見出しは言語ごとに違う文字列になるため。
- `guide-parity.test.sh` を足す。スクリプトの回帰テストで、一致・節の欠落・階層の違い・順序の入れ替え・コードブロック内の `#` の無視・日本語版の無い英語版、を作業用ディレクトリの小さな文書で確かめる。
- CI では、既存の `release-artifacts` ジョブに手順として足す（新しいジョブは作らない。ジョブ数「8」の記述を触らずに済む）。ジョブの名前は、手順書の整合も含む名前に直す。`ci-local.sh` の `release-artifacts` にも同じ手順を足し、`ci-local.test.sh` で `ci.yml` との一致を保つ。

### Release の tarball

- `build-release.sh` は `git ls-files … docs/guide` で追跡ファイルを入れるので、`docs/guide/en/` は自動で入る。
- `check-release.sh` の必須ファイルに `docs/guide/en/setup.md`・`docs/guide/en/access-control.md` を足す。`release.test.sh` の模擬ツリーとケースも合わせる。

### 英訳の方針

- 訳語は、英語の `README.md` が既に使っている語（「保全方式」の英訳など）に揃える。README に無い語は、この 2 本の中で一貫させる。
- コマンド、パス、変数名、画面の項目名、AWS のリソース名は原文のまま。画面の文言は、SPA の英語カタログ（`packages/web` の en）にある語に揃える。
- 日本語版にある来歴注記（`Issue #194 により 2026-10-23 追記` など）は、そのまま訳して残す。
- 実値（アカウント ID など）は書かない。日本語版にあるプレースホルダをそのまま使う。

### 入口の更新

- `README.md`・`README.ja.md`: 「手順書は日本語のみ」の記述を、「導入の手順（setup）と認証の選択（access-control）は英語版がある。ほかは日本語のみ」に直す。「Guides」の表で、この 2 本に英語版へのリンクを足す。見出しの構造・順序とリンクは 2 本で 1 対 1 に揃える。
- `docs/guide/README.md`: 目次の表に、英語版への案内を足す。

覆す・足す ID と節:

- `CLAUDE.md` 開発フローの README の項: 「`docs/guide/` は日本語のみで、英訳しない（Issue #179…）」を、「`setup.md` と `access-control.md` だけ `docs/guide/en/` に英語版を持つ。日本語が正本で、同じ PR で更新し、見出しの階層の列を `guide-parity.sh` が検査する（Issue #205）。ほかは日本語のみ」に直す。来歴は「Issue #205 により 2026-11-03 訂正」。
- `CLAUDE.md` の構成・コマンドの節: `guide-parity.sh` を足す。

- `docs/design/requirements.md`: Out of Scope の表（「…docs/guide/ の英訳…」の行）に、Issue #205 の訂正を足す。冒頭の追記注記（Issue #179・#94）の「`docs/guide/` は日本語のみ」も、同じ来歴で直す。要件文（FR・NFR）は覆さない。NFR-4・SM-2 は変えない。ID と節番号は変えない。

- 上の記述は、plan で `日本語のみ`・`英訳` を grep して同種の古い記述を総当たりし、同じ来歴で直す（結果を plan に記録する）。`aidlc/` と、凍結済みの過去の spec・plan は書き換えない。
- `docs/design/` の FR・画面・IAM の記述は、ほかに触れない。

## 検証

- `guide-parity.test.sh` を TDD で書く（失敗を確かめてから実装）。
- 実際の 2 組の文書で `guide-parity.sh` が通ること。日本語版の見出しを 1 つ消して、落ちること（確かめたら戻す）。
- `release.test.sh`、`ci-local.test.sh`、`./.github/scripts/ci-local.sh release-artifacts`、`protected-values-guard.sh`、gitleaks。
- 英語版の相対リンクが、ファイルとして実在すること（grep と存在確認の機械判定）。
- 手順書の英語版は「文面を読むのではなく経路として実行して確かめる」の原則に従う。ただし手順の内容は日本語版と同一で、日本語版は検証済み（#221〜#224、#242）のため、今回は訳の忠実さを日本語版との突き合わせで確かめる。

## 私の判断（依頼者が確認する点）

1. 検査を新しいジョブにせず、既存の `release-artifacts` ジョブの手順にした（ジョブ数の記述を増やさないため）。
2. 検査するのは見出しの階層の列だけにした（依頼は「数と順序」。リンクとコードブロックの数の一致は、効果は大きいが依頼の外なので足さない）。
3. 英語版どうしでリンクし、英訳していないページへは日本語版へ「(Japanese)」付きで向ける。
4. 日本語版の冒頭にも言語切替の行を足す（日本語版を触るのはこの 1 行だけ）。
5. README の整合検査は足さない。
