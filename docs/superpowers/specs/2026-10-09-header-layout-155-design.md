# 見出し行の配置と横幅の見直し 設計（Issue #155）

- Issue: #155（見出し行の余白を詰め、編集域を広くする。全画面を点検。横幅の上限を撤廃）
- 日付: 2026-10-09
- 経路: architectural（正本 `docs/design/` の改訂を伴い、複数画面の配置をまたぐため）

## 背景

画面上部の見出しまわりは、見出し・件数・操作・絞り込みが別々の行に分かれている。そのため表やマトリクスの編集域が狭い。また、`AppShell` の `maxContentWidth={1440}` と表の内容幅の指定により、ブラウザを広げても IAMロール割り当て画面が広がらない。

## 決定事項

依頼者との対話で次を決めた（2026-10-09）。

1. **横幅の上限は設けない。** `AppShell` の `maxContentWidth={1440}` を外す。表はコンテナ幅に合わせる。
2. **見出しまわりの配置は「点検して、同じ構造の画面は同じ配置に揃える」。** 画面ごとに変えるかどうかは本 spec の一覧で決める。
3. **IAMロール割り当て画面は A 案（2 行に収める）。** 1 行目に見出しと件数、2 行目に件数の文言・フィルタ欄・操作ボタン。

## 設計

### 1. IAMロール割り当て画面（`MatrixScreen`）

- 1 行目: 見出し「IAMロール割り当て」と件数「IAMユーザ N / IAMロール M」を同じ行に置く。
  - Cloudscape の `Header` は `description` を見出しの下に出すため、`ContentLayout` の header に自前の行（`flex`）を置く。既存の `DiffScreen` が同じく header に自前の要素を置いている。
- 2 行目: 件数の文言（「N 件の IAMロールを選択中 · M 件の IAMロールを除外 · 変更 K 件」）を左、フィルタ欄（`Input type="search"`、最大幅 `24rem` を維持）を中央、「変更を取り消す」「申請を作成」を右に並べる。
  - 操作ボタンを含むツールバーは、ページ階層に置く（`frontend.md` の規約）。`AssignmentMatrix` の中には入れない。
  - 2 行目は `flex-wrap` で折り返しを許す。狭い幅（1024px 付近）では操作ボタンが次の行へ下がる。どの要素を先に下げるかは実測して決める。
- 「表示 N / 全 M 行」（絞り込みの状態）、「非表示の列」の状態行、凡例、保存中の表示は、今のまま表の周りに残す。

### 2. 他の 4 画面

どの画面も「`Header`（h1）の下に件数（description）がある」構造であり、件数を見出しと同じ行へ移す。

| 画面 | 1 行目（見出し行） | 残すもの |
|---|---|---|
| IAMユーザ（`PoolScreen`） | 見出し・件数・「ユーザを新規登録」「属性の項目を編集」 | 絞り込み欄と「属性一括編集モード」の行（既に 1 行） |
| IAMロール管理（`RolesScreen`） | 見出し・件数・「並び順を編集」「ロールを新規登録」 | 並び順編集中のバー |
| 申請履歴（`HistoryScreen`） | 見出し・件数 | 表の中の絞り込み（状態・検索） |
| 差分確認・反映（`DiffScreen`） | 見出し・件数・「選択した N 件を反映」 | 見出しの上の「← IAMロール割り当てへ戻る」（導線。行は 1 つ増えたまま） |

件数は、いずれの画面も `Header` の `description` の文字列をそのまま使う（文言は変えない）。

### 3. 横幅

- `packages/web/src/components/AppShell.tsx`: `AppLayout` の `maxContentWidth={1440}` を外す。
- `packages/web/src/components/MatrixGrid.tsx`: マトリクスの `<table>`（`tableStyle`）を `width: 100%` にし、列はコンテナ幅に合わせて配分する。外側の `overflow: auto` のスクロール領域（`data-testid="matrix-scroll"`）は残す。列の最小幅・最大幅（`columnHeaderStyle` など）は変えない。
- 1024px 未満の非対応表示（`viewport-unsupported`）は変えない。

### 4. `.gitignore`

- `.superpowers/` を `.gitignore` に追加する（ブレインストーミングの作業ファイルを Git に入れないため）。

## テスト方針（TDD）

アプリコード（`packages/web/`）は失敗するテストを先に書く。

- IAMロール割り当て画面:
  - 見出しと件数が同じ行にある（同じ親の `flex` 行の中にある）
  - 件数の文言・フィルタ欄・操作ボタンが 2 行目にある
  - 表が `width: 100%` である（インラインスタイルで確かめる）
- 他の 4 画面: 件数が見出しと同じ行にあること。件数の文言が変わらないこと（既存のテストの期待値を維持）。
- 既存のテストは、件数の文言・ボタンのラベル・`data-testid` を変えない限り通ること。
- `AppShell`: `maxContentWidth` を渡さないことを確かめるテストを足す（レイアウトの実値は実測で確かめる）。

## 実測

jsdom では配置と幅の実値が出ないため、ブラウザで確かめる（開発サーバーで行い、必要なら本番でも行う）。

- 幅 1024px・1440px・1920px 以上の 3 つで、次を測る。
  - 見出しから表の先頭行までの高さ（縮んだこと）
  - 表の幅（コンテナ幅に合っていること。1920px で表が 1440px に止まらないこと）
  - 2 行目の折り返し（1024px 付近で崩れないこと）
- 4 画面の見出し行を、同じ幅で目視する。
