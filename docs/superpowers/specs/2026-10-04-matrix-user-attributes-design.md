## 1. 背景と目的

IAM ユーザの属性（Issue #61。ユーザプールごとに最大 10 列の属性列を定義し、ユーザごとに値を持つ）は、ユーザプール画面でしか見えない。割り当てマトリクスの行見出しはユーザ名とアカウント ID だけで、どのユーザがどの部署・役割なのかを、マトリクスを見ながら判断できない。

本 Issue では、マトリクスに属性列を出し、ロール列と同じ操作（ヘッダの「▾」メニュー）でソート・フィルタできるようにする。#106（ユーザ名・アカウント ID のテキスト絞り込み）で「属性による絞り込みは #107 の後」とした分を、ここで回収する。

### 現状の確認（読んだ事実）

- マトリクスの API（`GET /pools/:poolId/matrix`）は、すでに属性を返している。`MatrixView.pool.attributeColumns` に列の定義、`MatrixView.users[].attributes` に値（`pruneAttributes` で、定義された列のものだけに整えたもの）が入る（`packages/api/src/handlers/matrix.ts`）。**API・core・DynamoDB は変えない。**
- `MatrixRow`（`MatrixGrid.tsx`）は `userArn` / `userName` / `accountId` だけで、属性を持たない。
- ローミング tabindex は、`focus = { row, col }` で、ヘッダ行は `row = -1`、`col` はロール列の添字。属性列はこの添字の外にある。
- 本番の `jump-account` には属性列が 2 つある（読み取りで確認済み）。実測は読み取りだけでできる。

### 成功基準

1. 行見出し（ユーザ名）の右に、プールの属性列が定義の順で並び、各行にユーザの値が出る。値が無いセルは「—」。属性列が 0 件のプールでは何も増えない。
2. 属性列の見出しの名前をクリックすると、その列が細い列に畳まれる。細い列のクリックで開き直せる。畳んだ列の値は、テキストの絞り込みの照合から外れる。
3. 属性列の見出しに「▾」があり、ロール列と同じ形のメニュー（ソート・フィルタ・列）が開く。ヘッダのセルで Enter を押しても開く。
4. ソートは 1 列だけ有効（ロール列と属性列のどちらでも、最後に指定した列が有効）。属性のソートは日本語の並びで比べ、値の無いユーザは昇順でも降順でも最後。同順の行は元の順。
5. 属性のフィルタは、その列に実在する値と「（未設定）」から 1 つ選ぶ。列をまたいで AND で、ロール列のフィルタ・テキスト絞り込みとも AND。
6. 条件のある属性の見出しにバッジを出す。畳んだ列は「●」を出す。件数の行「表示 n / 全 m 行」と「すべて解除」は、ロール列の条件と共用で、属性の条件も外す。
7. マトリクスの Tab 停止点は 1 つのまま（M-1.3）。属性の見出しもローミング tabindex に入り、左右の矢印キーでロール列と行き来できる。ロール列の既存のキー操作（矢印・Home / End・Enter・Space）は変えない。
8. 列ヘッダの「変更 n」と「申請に含める」は、絞り込みに関係なく全行で数える（D-8）。セルのチェックでは、表示する行も順序も変えない（D-7）。
9. `packages/api`・`packages/core`・`infra/` を変えない。保存も AWS への書き込みも無い。

## 2. 決定事項

| ID | 事項 | 決定 | 出所 |
|---|---|---|---|
| D-1 | 見せ方 | 属性の**列名は列ヘッダ、値は各行のセル**。行見出しの右に、ロール列の手前に並べる | 依頼者の承認（画面案） |
| D-2 | 固定 | 固定するのは行見出しだけ（既存）。属性列はロール列と一緒に横へスクロールする。幅は最小 8.5rem・最大 14rem で、長い値は折り返す | 導出: 属性列は最大 10 列で、複数列を固定にすると固定領域が画面を占める。幅の計算も要らない |
| D-3 | 畳み・開き | 見出しの名前のクリックで畳み、細い列（幅 2.25rem。「▸」と縦書きの属性名）のクリックで開く。メニューの「列」グループの「この列を畳む」でも畳める。状態は保存せず、プールの切り替えと読み直しでリセットする | 依頼者の要望（「属性名のラベルをクリックしたら、表示／非表示を切り替えられるように」）。保存しない点は #91・#106 の D-6 と同じ（共有 1 アカウントで利用者ごとの保存先が無い） |
| D-4 | 既定 | すべて表示 | 導出: プールで定義した列は見る前提。隠すほうを操作にする |
| D-5 | 操作手順 | ロール列と同じ。見出しの「▾」（`tabIndex=-1`）とヘッダのセルの Enter でメニューを開く。メニューは「ソート」「フィルタ」「列」の 3 グループ | 依頼者の指示（「ロールと同じような操作手順にしたい」） |
| D-6 | ソートの規則 | 1 列だけ。ロール列と属性列をまたいで、最後に指定した列が有効。属性は昇順／降順／解除。比較は `Intl.Collator("ja")`。値の無いユーザは常に最後。同順は元の順（安定） | 依頼者の要望。1 列だけは #91 の D-4。値の無いユーザを最後にするのは導出（降順で空が先頭に来ると、実在する値が見えない） |

| D-8 | フィルタの規則 | 属性ごとに 1 つの値（または「（未設定）」）。値の一覧は、そのプールの全ユーザから作る（絞り込みの結果に依存しない）。件数は全ユーザでの件数 | 導出: 一覧が条件で変わると、選び直しのたびに候補が動く。#91 のロール列のフィルタも全行を基準にしている |
| D-9 | テキスト絞り込みとの関係 | #106 の入力欄は、**畳んでいない属性列の値**にも照合する（ユーザ名・アカウント ID・属性値のどれか）。畳んだ列は照合しない。属性のメニューのフィルタは、畳んでいても効く | 導出: 見えない列で行が消えると分かりにくい。一方、メニューのフィルタは明示的な操作で、バッジ／印が残る |
| D-10 | 畳んだ列の条件の表示 | 条件（ソート・フィルタ）のある畳んだ列は、細い見出しに「●」を出す。件数の行の「すべて解除」はそれらも外す | 導出: 畳むと見出しのバッジが見えなくなる。条件を忘れたまま行が足りないと誤解するため |
| D-11 | 適用の時点 | 条件を変えたときだけ表示する行と順序を確定し直す。セルのチェックでは再計算しない（#91 の D-7）。畳み・開きは条件ではないので再計算しない（テキスト絞り込みの照合の対象だけが変わるので、畳み・開きのとき、テキストが空でなければ確定し直す） | 導出: 畳み・開きでテキストの照合対象が変わるため |

## 3. 設計

### 3.1 純粋関数（`packages/web/src/matrix-view.ts`）

```ts
export type AttributeSortOrder = "asc" | "desc";
export const ATTRIBUTE_UNSET = "\u0000unset"; // 「（未設定）」の選択値。実在する値と衝突しない

export type ViewSort =
  | { kind: "role"; roleArn: string; order: SortOrder }
  | { kind: "attr"; columnId: string; order: AttributeSortOrder };

export interface MatrixViewState {
  filters: Record<string, ColumnFilter>;       // ロール列（既存）
  attrFilters: Record<string, string>;         // 属性列: columnId → 値 または ATTRIBUTE_UNSET
  sort: ViewSort | null;
  userText: string;
}

export function withAttrFilter(state, columnId, value: string | null): MatrixViewState;
export function withAttrSort(state, columnId, order: AttributeSortOrder | null): MatrixViewState;
/** 属性列の、実在する値（照合順）と件数、未設定の件数。全ユーザから作る（D-8）。 */
export function attributeValueOptions(users, columnId): { values: { value: string; count: number }[]; unset: number };
```

- `computeVisibleUserArns` は、第 4 引数 `textOf` に加えて、属性の値を引く関数（`attributeOf(userArn, columnId)`）を受ける。属性フィルタ → ロール列フィルタ → テキスト → ソートの順で適用する。テキストの照合文字列は、呼び出し側が「ユーザ名・アカウント ID・畳んでいない属性値」で作る（D-9）。
- 属性のソートは `Intl.Collator("ja")` で比べる。値の無いユーザは、昇順・降順のどちらでも最後（D-6）。
- `withSort` は、既存の呼び出しに合わせて `{ kind: "role", … }` を作る。`isViewActive` は属性のフィルタと属性のソートも見る。

### 3.2 `AssignmentMatrix`

- props に `attributeColumns: AttributeColumn[]` を足す（`MatrixScreen` が `matrix.pool.attributeColumns` を渡す）。
- 畳んだ列の集合 `folded: ReadonlySet<string>` を状態に持つ。プールの切り替え・読み直しでは `AssignmentMatrix` が外れるのでリセットされる。
- `MatrixRow` に `attributes: Record<string, string>` を足す。`rows` の組み立てで `user.attributes` を渡す。
- 絞り込み欄のプレースホルダーは「ユーザ名・アカウント ID・属性で絞り込み」。
- 件数の行・0 件の本体・「すべて解除」は既存を使い、属性の条件も外す。「すべて解除」の後のフォーカスは、既存どおりマトリクスの Tab 停止点へ移す。

### 3.3 `MatrixGrid`

- props に `attributeColumns`、`foldedColumnIds`、`attributeView`（列ごとの `{ filter, sort }`）、`onToggleFold`、`onChangeAttributeFilter`、`onChangeAttributeSort`、`attributeOptions`（列ごとの値の一覧）を足す。
- ヘッダ行: 角のセルの右に、属性列の `th`（`scope="col"`）を並べる。畳んでいない列は「名前（クリックで畳む）」と「▾」とバッジ、畳んだ列は「▸」と縦書きの名前（クリックで開く）と、条件があれば「●」。本体: 属性列の `td`（値、無ければ「—」。畳んだ列は縞模様で値を出さない）。
- ローミング tabindex: `focus.col` を、ヘッダ行では「属性列 ＋ ロール列」の連続した添字として扱う（D-12）。本体の行の `col` は、ロール列の添字のまま（既存のテストと `data-testid` を壊さない）。`register` / `isFocused` / `handleKeyDown` は、ヘッダ行だけ属性列ぶんだけ添字をずらす。
- メニュー: 開く列の種類（ロール列か属性列）を持つ。属性のメニューは、ヘッダのセルの Enter または「▾」で開く（D-5）。
- 属性の見出しの `th` は `tabIndex`（ローミング）を持つ。「▾」と畳みのボタンは `tabIndex=-1`。

### 3.4 `ColumnMenu`（一般化）

- 項目のグループ（見出しと、`menuitemradio` / `menuitem` の項目）を props で受ける。ロール列は、従来のグループ（ソート 3 項目、フィルタ 4 項目）を渡す。属性列は、ソート（昇順／降順／解除）、フィルタ（すべて／実在する値／（未設定））、列（この列を畳む）を渡す。
- ポータル、キー操作、フォーカスの復帰、スクロールで閉じる動作は変えない。メニューが長くなる（値が多い）場合は、`maxHeight` を付けてメニュー内でスクロールする。

### 3.5 失敗と競合

- 保存も API も無いので、新しい失敗の経路は無い。
- 属性の値が極端に多い列（ユーザ数が多く値がばらばら）では、メニューが長くなる。上限を設けず、メニュー内のスクロールで扱う（値の検索は範囲外）。
