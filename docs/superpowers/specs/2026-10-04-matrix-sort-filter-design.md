# 割り当てマトリクスの列のソート・フィルタと、列ヘッダ行の固定の修正 — 設計

- 日付: 2026-10-04
- Issue: #91（分割後の範囲。残りの「並べ替え」と「背景色」は #100）
- ブランチ: `feat/91-matrix-sort-filter`
- 状態: spec レビュー待ち

## 1. 背景と目的

Issue #91 は、割り当てマトリクス（`docs/design/` の画面 3。Issue は「画面 2 周辺」と書いたが、正本ではマトリクスは画面 3）の操作性を上げる 3 項目の要望だった。依頼者の決定（2026-10-04）で次のように分けた。

- **本 Issue（#91）**: 列のソート・フィルタ。あわせて、列ヘッダ行が縦スクロールで固定されていない不具合を直す。いずれもフロントだけで、保存も API も要らない。
- **#100**: 列の並べ替えと背景色。保存先（DynamoDB）と API を伴うので別 spec・別 PR にする。

IAM ユーザの件数が増えると、マトリクスは縦にスクロールする。このとき、どのロール列かを示す列ヘッダが視界から消えると、交点のチェックの意味が失われる。ソート・フィルタは、その縦長のマトリクスから目的のユーザ行を探すための操作である。

### 不具合: 列ヘッダ行が縦スクロールで固定されていない

`MatrixGrid.tsx` の列ヘッダは `position: sticky; top: 0` を持ち、`mockups.md`（画面 3 の設計メモ「行ヘッダ・列ヘッダをスクロール固定」）と `interaction-spec.md`（レスポンシブの表）も固定を求めている。しかし、外側の `<div style={{ overflowX: "auto" }}>` が原因で、縦方向には効かない。

- `overflow-x` に `auto` を指定すると、`overflow-y` は `visible` ではなく `auto` として扱われ、この div がスクロールコンテナになる。
- `position: sticky` は最も近いスクロールコンテナを基準にする。この div には高さの上限が無く、縦にはスクロールしないので、`top: 0` はページの縦スクロールに対して何も固定しない。
- 横方向の行ヘッダ列（`left: 0`）の固定は、この div が横にスクロールするので効く。

### 成功基準

1. 列ヘッダの「▾」メニューから、その列のソート（チェックありを上に／チェックなしを上に／解除）とフィルタ（すべて／チェックあり／チェックなし／未反映の変更あり）を設定できる。メニューはキーボードだけでも操作できる。
2. 複数の列のフィルタは AND で効き、ソートは 1 列だけが有効で、同順の行は元の順を保つ。
3. セルのチェック操作では、表示する行も順序も変わらない（操作中に行が消えたり動いたりしない）。
4. 絞り込み中は、列ヘッダにバッジが出て、「表示 n / 全 m 行」と「すべて解除」が見える。結果が 0 件でも列ヘッダは残り、解除できる。
5. 列ヘッダの「変更 n」と「申請に含める」は、絞り込みに関係なく全行で数える。申請を作成する対象も変わらない。
6. ユーザ行が多く縦にスクロールするとき、列ヘッダ行（と角のセル）が、マトリクスの内側のスクロールの中で固定される（実測する）。
7. Tab 停止点は、ヘッダ行を含むマトリクス全体で 1 つのまま（M-1.3）。矢印キー移動・Home / End・Space のチェック切替は変わらない。
8. `packages/api`・`packages/core`・`infra/` を変えない。

## 3. 設計

### 3.1 純粋関数（`packages/web/src/matrix-view.ts`）

```ts
export type ColumnFilter = "checked" | "unchecked" | "changed";
export type SortOrder = "checked-first" | "unchecked-first";

export interface MatrixViewState {
  /** ロール ARN → フィルタ。無い列は「すべて」。 */
  filters: Record<string, ColumnFilter>;
  /** ソート中の列。無ければ元の順。 */
  sort: { roleArn: string; order: SortOrder } | null;
}

export const EMPTY_VIEW: MatrixViewState;

/** 表示するユーザ ARN を、表示する順で返す。 */
export function computeVisibleUserArns(
  userArns: readonly string[],
  cellOf: (userArn: string, roleArn: string) => { checked: boolean; reflected: boolean },
  state: MatrixViewState,
): string[];

export function isViewActive(state: MatrixViewState): boolean;
/** 列のフィルタを足す・外す（`null`）。ほかの列の条件は保つ。 */
export function withFilter(state: MatrixViewState, roleArn: string, filter: ColumnFilter | null): MatrixViewState;
/** ソートを設定・解除（`null`）する。ソートは 1 列だけなので、前の列のソートは置き換わる。 */
export function withSort(state: MatrixViewState, roleArn: string, order: SortOrder | null): MatrixViewState;
```

- フィルタは「`checked`」＝チェックあり、「`unchecked`」＝チェックなし、「`changed`」＝`checked !== reflected`。交点の無いユーザ×ロールは `checked = reflected = false` として扱う（既存の `cellState` と同じ）。
- ソートは安定。元の順は `userArns` の並び。

### 3.2 `AssignmentMatrix`（状態と適用の時点）

- 状態は 2 つ持つ。条件（`MatrixViewState`）と、確定した表示順（`visibleUserArns: string[] | null`。`null` は「条件なし」で、`users` の順をそのまま使う）。
- 条件を変えるハンドラの中で `computeVisibleUserArns` を呼び、確定した表示順を条件と同時に更新する（D-7）。ハンドラは、そのとき最新の `assignments` を ref から読む。
- マトリクスの読み直しとプールの切り替えでは、`MatrixScreen` が読み込み中の表示（スピナー）に切り替えて `AssignmentMatrix` を外すので、2 つの状態は初期値に戻る。`AssignmentMatrix` 側に再計算の処理は足さない。セルの保存（`patch`）は `assignments` だけを新しくし、読み込み中の表示を挟まないので、条件も確定した表示順も保たれる。
- したがって、確定した表示順に無いユーザは生まれない（`users` は `AssignmentMatrix` の生存中は変わらない）。
- `MatrixGrid` には、表示する `rows` と、列ごとの条件（`columnView: Record<roleArn, { filter, sort }>`）、メニューの操作のコールバック（`onChangeFilter`・`onChangeSort`）を渡す。`MatrixGrid` は計算しない。

### 3.3 `MatrixGrid` とメニュー

- 列ヘッダのロール名の行の右に「▾」ボタン（`aria-haspopup="menu"`、`aria-expanded`、`aria-label="<ロール名> のソートとフィルタ"`、`tabIndex=-1`）。条件のある列は、ロール名の下にバッジ（「チェックあり↑」「絞り込み: チェックあり」）。
- メニュー（`ColumnMenu`。`MatrixGrid.tsx` と同じディレクトリに置く）:
  - 見出し「ソート」と、`menuitemradio` の 3 項目（チェックありを上に／チェックなしを上に／解除）。
  - 見出し「フィルタ」と、`menuitemradio` の 4 項目（すべて／チェックあり／チェックなし／未反映の変更あり）。
  - 矢印キーで項目間を移動し、Enter / Space で選んで閉じる。Escape・外側のクリックで、何も変えずに閉じる。
  - 開いたとき、現在の項目にフォーカスする。閉じたとき、フォーカスを開く前のヘッダ位置（ローミング tabindex の要素）へ戻す。
  - `document.body` へのポータルで、トリガーの `getBoundingClientRect()` の下に描く。スクロールとリサイズで閉じる（位置のずれを避ける）。
- ヘッダのフォーカス位置の `onKeyDown` に、Enter でメニューを開く処理を足す（既存の矢印キー・Home・End は変えない）。
- 除外列（`lock` あり）と「変更なし」の列も、ソート・フィルタの対象にする（値は `checked` で、申請の可否とは別）。

### 3.4 絞り込み中の表示

- マトリクスの上（警告帯の下）に件数の行を出す。条件が無いときは出さない。
  > 表示 12 / 全 480 行　[すべて解除]
- 件数は `aria-live="polite"` の領域に入れる（条件を変えたときに読み上げられる）。
- 0 件のとき、本体は 1 行（`colSpan` で全列）の「条件に一致するユーザがいません。[すべて解除]」。列ヘッダと件数の行は残る。
- 凡例（`matrix-legend`）に、ソート・フィルタの説明は足さない。

### 3.5 列ヘッダ行の固定（D-13）

- `matrix-scroll` の div に `maxHeight` と `overflow: auto` を付ける。`overflowX` だけの指定をやめる。
- 高さはヘッドレス Playwright で実測して決める。ユーザ行が少ないときは、マトリクスの高さが内容に収まり、余白ができない（`maxHeight` なので上限だけ）。
- 角のセルと列ヘッダの `z-index`・背景は変えない。メニューのポータルは `z-index` をヘッダより上にする。

### 3.6 失敗と競合

- 保存も API も無いので、新しい失敗の経路は無い。
- 絞り込み中にセルの保存が失敗しても、画面は操作前のまま（既存の挙動）で、表示する行も変わらない。
- 絞り込み中に「変更を取り消す」を行うと、読み直し（`reload`）で条件はリセットされ、全行が表示に戻る。
