# Rolust の概要

AWS IAMロールの**信頼ポリシー**（`AssumeRolePolicyDocument`）を、申請とレビューを経て反映する管理ツールです。IAMユーザのまとまり（ユーザプール）と IAMロールの割り当てをマトリクスで編集し、差分を確認したうえで明示的に反映を指示します。反映のとき、Rolust が管理していないプリンシパル（サービスプリンシパル、他アカウントの root、フェデレーテッド ID など）は一切削除されず、そのまま残ります。

## できること

- **IAMユーザのプール管理**: ユーザプールはデプロイにつき 1 つです。複数の AWS アカウントの IAMユーザを 1 つのプールに混在できます。登録した IAMロールは、そのままプールに紐づきます。ロールの登録のとき、信頼ポリシーにいる IAMユーザをプールへ取り込みます。プールごとに属性列（最大 10 列）を持ち、IAMユーザごとに値を登録できます（画面 1。マトリクスと申請には出ません）。IAMユーザの登録は、1 件ずつの入力のほか、属性つきの CSV の貼り付けで一括登録できます（登録済みのユーザは変更しません）。
- **IAMロールの登録**: 管理対象は、ロールに付いたタグで絞り込みます。別アカウントのロールも登録できます（ターゲット側の準備は [cross-account.md](cross-account.md)）。任意の説明を登録・一覧行から編集でき、割り当てマトリクスの列ヘッダにも表示されます。ロールの背景色を固定パレットの 8 色から選べます（AWS へは書き込まず、マトリクスの当該ロールの列のヘッダに付きます）。未反映（下書き / 失敗）の申請が無いロールは削除できます（割り当てごと消えます。AWS 上のロールと信頼ポリシーは変わりません）。
- **ユーザ × ロールのマトリクス編集**: この時点では AWS へ一切書き込みません。列の並び順は IAMロール画面の「並び順を編集」で変えて保存できます。ユーザプールの属性列はマトリクスの行見出しの右に出て、見出しの名前のクリックで畳め、「▾」メニューで属性の値によるソート・フィルタができます。
- **申請の作成と差分確認**: 追加・削除されるプリンシパルの差分を確認し、管理外のプリンシパルには警告が出ます。
- **信頼ポリシーの乖離の確認**: IAMロール管理画面の「信頼ポリシーを確認」を押したときだけ、登録済みの全ロールについて、Rolust に記録した反映済みの割り当てと実際の信頼ポリシーを読み取りで比べ、足りない・余分なユーザを示します。Rolust の外から信頼ポリシーが変えられたことに気づくための確認で、結果は保存せず、画面を再読み込みすると消えます。確認自体は AWS へ書き込まず、申請も作りません。
- **信頼ポリシーの乖離を直す**: 乖離のあるロールの「詳細」から、ロール 1 本ごとに、どちらを正とするかを選びます。「IAM を記録に合わせる（申請を作成）」は、Rolust の記録を正として、信頼ポリシーを戻す下書きの申請を作り、差分確認で反映を指示します。「記録を IAM に合わせる」は、信頼ポリシーを正として、Rolust の記録（割り当て）を更新します（AWS は書き換えません）。違いは [managed-roles.md](managed-roles.md) の「信頼ポリシーの乖離を直す」にあります。
- **管理外を残したままの信頼ポリシーへの反映**: ロール単位で成否を表示し、失敗した申請は再反映できます。
- **アクセス制限**: Basic 認証または Amazon Cognito による管理画面のアクセス制限、IP アドレス制限（任意）、API Gateway の直 URL の遮断（[access-control.md](access-control.md)）。
- **日本語と英語の表示**: 画面右上で切り替えます。

## できないこと

| できないこと | 理由 |
|---|---|
| IAMユーザの実在確認 | 手入力のみを情報源とします |
| ターゲットアカウント側のロール（Reader・Manager）の作成 | Rolust は作りません（`iam:CreateRole` を持ちません）。別アカウントのロールを操作するには、ターゲット側に `RolustTrustPolicyReader`・`RolustTrustPolicyManager` を、同梱の CloudFormation テンプレート（`cloudformation/target-roles.yaml`）で作ります（[cross-account.md](cross-account.md)）。Terraform モジュールと StackSets は提供しません |
| 権限ポリシー（インライン / アタッチ）の編集 | Rolust が扱うのは信頼ポリシーのみです |
| 承認の工程（状態・承認者） | 持ちません。反映の権限（`applier`）を持つ人が「反映」を押します。参照・作成・反映の権限は Cognito のグループで分けます（`auth_mode = "cognito"` のとき。[access-control.md](access-control.md)） |
| 管理者エンティティ | poc の対象外です（実行者の名前は記録します） |
| ページング・検索・仮想化 | 大規模を前提にした作り込みをしない方針です |
| モバイル表示 | デスクトップ専用です（1024px 以上） |

## 構成

```
CloudFront ──(viewer-request: Lambda@Edge 認証)────────┬──▶ S3        SPA（React + Cloudscape）
                                                       └──▶ API GW ──┬──▶ Lambda crud   + iam:ListRoleTags（登録時のタグ検証）/ iam:GetRole（登録時の取り込み）
                                                                      ├──▶ Lambda diff   + iam:GetRole
                                                                      └──▶ Lambda apply  + iam:UpdateAssumeRolePolicy
```

**Lambda を 3 系統に分ける理由**: `iam:UpdateAssumeRolePolicy` は特権昇格の経路になりうるため、全 Lambda に配りません。マトリクス操作を担う crud Lambda が持つ IAM 権限はロール登録時のタグの読み取り（`iam:ListRoleTags`）と、ロール登録時の信頼ポリシーの読み取り（`iam:GetRole`。管理対象タグの付いたロールだけ）だけで、書き込み権限を持たないので、マトリクスの操作（チェックの増減）では AWS へ書き込まない、という保証は、権限の設計として構造的に成り立ちます。

## 第三者のライセンス

Rolust 自身のライセンスは、リポジトリ直下（Release の tarball の直下）の `LICENSE`（Apache License 2.0）です。

管理画面（SPA）には、第三者のソフトウェア（React や AWS Cloudscape など）が含まれます。そのライセンスの全文と NOTICE は、ビルドのたびに `THIRD-PARTY-NOTICES.txt` として `packages/web/dist/` に作られ、Release の tarball にも入ります。デプロイした管理画面では、`/THIRD-PARTY-NOTICES.txt` で読めます（管理画面と同じ認証の内側です）。

Lambda（crud・diff・apply・Lambda@Edge）のバンドルは、第三者のコードを含みません。`@aws-sdk/*` は外部化していて、Lambda のランタイムが提供します。

## 表示言語

管理画面は日本語と英語で表示できます。

- **切り替え**: 画面右上の言語名（日本語 / English）を押して選びます（Cognito 認証ではログアウトの左）。切り替えると、画面の文言、タブの題名、Cloudscape の部品の文言が同時に変わります。
- **初回の言語**: 選択を保存していなければ、ブラウザの言語に従います（先頭の言語が `ja` なら日本語、それ以外は英語）。
- **選択の保存**: 選んだ言語は、そのブラウザの localStorage（`rolust.locale`）に保存します。サーバには保存しないので、ブラウザや端末ごとに選びます。
- **API のエラーと結果**: 本文は選んだ言語で出ます。エラーコード（`AccessDenied` など）は言語に依らず併記します。

既知の限界:

- 一括登録の CSV の見出し列名は、英語の画面でも `ユーザ名` のままです（データ形式の識別子であり、英語の画面でも、入力欄の 1 行目に初期入力されるヘッダ行にそのまま出ます）。
- 表示言語の切り替えを入れる前に記録した反映結果と、AWS が返した文言は、記録された言語（日本語または英語）のまま出ます。英語の画面でも、旧い記録の本文は日本語です。
- 設計文書（`docs/design/`）と、この手順書は日本語のままです。
